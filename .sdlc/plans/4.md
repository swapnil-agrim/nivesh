### Decisions on the research's unverified risks
1. **Keyring in containers**: `get_secret` already reads env first, then keyring, swallowing backend errors. In Docker/VM, secrets are injected as env vars (compose `environment`/`env_file`, never baked into image). `nivesh secrets set` on a host with no usable backend exits 1 with a message pointing to env injection; it never falls back to writing a file. Tests use an in-memory `KeyringBackend` fixture (`fake_keyring` in `tests/conftest.py`), never the real keychain.
2. **age availability**: backup/restore call `_encrypt`/`_decrypt` (two small functions around `subprocess.run(["age", ...])`). Unit tests monkeypatch both with a reversible fake, so retention/tar/restore logic is always tested. One real round-trip test is `skipif(shutil.which("age") is None)`. The Dockerfile installs `age`. Missing binary at runtime gives a clear `NiveshError`. Recipient (public key) comes from config; the identity file path is a `restore --identity` argument; neither is a secret value.
3. **Agent SDK usage fields**: at the start of B2 read the pinned `claude_agent_sdk` (0.2.165) types in the venv (`ResultMessage`, `AssistantMessage`, `TextBlock`, `ToolUseBlock`, `ToolResultBlock`, `UserMessage`, usage dict, `total_cost_usd`, `model_usage`). Tracer reads them defensively (`getattr`, `dict.get`, default 0). Tests build fakes of those exact classes (or `SimpleNamespace` with the verified field names) and never call the SDK. If a field is absent the trace stores `null` and cost falls back to 0 with `cost_source: "none"`.
4. **Digit-run false positives** (Rule R, replaces the blanket 9-18 digit sweep for in-text matches): a bare digit run of 9-18 digits is masked only when (a) it is the entire string value, or (b) it directly follows a label word (`a/c|acct|account|folio|client|dp|phone|mobile|mob|pan|aadhaar`, case-insensitive, up to 3 separator chars). Runs adjacent to `.` or `,` or inside a decimal/grouped number are never masked. So `"market cap 1234567890123"` and prices pass, `"folio 12345678901"` and `"98765 43210"`-style spaced phones are masked. Numeric JSON values are untouched (existing behaviour); sensitive numeric values are caught by key name. Existing `tests/core/test_redact.py` and `tests/adapters/test_recorder.py` expectations that assumed the blanket sweep are updated with the reason noted in the test; recorder fixtures must still be redacted (re-run to prove).
5. **Migration 0002 on the v1 fixture**: `0002_run_trace.sql` only `ALTER TABLE run ADD COLUMN ... DEFAULT` (no table rebuild). A test loads `tests/fixtures/db/v1_sqlite.sql`, seeds a run row, applies the REAL sqlite migrations dir, asserts old rows intact, version 2, new columns default, rerun no-op.
6. **Test literals**: the commit secret-scanner refuses credential/PAN/token-looking literals. All dummy values come from `tests/pii_values.py`, which builds them by concatenation (`"ABCDE" + "1234" + "F"`, `"sk" + "-" + "x" * 20`, `"+91" + "98765" + "43210"`, email `"owner" + "@" + "example.com"`, etc.). No test, fixture file, or doc may contain a whole such literal. Fixture files needing PII are generated into `tmp_path` at test time. No `.gitleaks.toml` unless gitleaks flags something (then allowlist the path, not a pattern).
7. **Redaction placement**: one pattern table in `nivesh_core/redact.py` feeds both `redact_text` and the new scanner (single source), so scanner and redactor cannot drift. All redaction masks to the existing `MASK` (no per-kind hashing; hashing deferred, ponytail: removal satisfies "removes or hashes").
8. **Cost currency**: price table in config as USD per million tokens; `usd_inr` in config. Cost = tokens x table price x `usd_inr` when the model is in the table, else `total_cost_usd x usd_inr` if the SDK gave one (`cost_source: "sdk"`), else 0. Cap is read from `Profile.monthly_cost_cap` (already exists), not a new Settings field.
9. **Run dir (ST-1.7 gap)**: `<data_dir>/runs/<run_id>/trace.jsonl`, dir 0700, files 0600 via `write_private`/`os.open`. `run_id` is the `run.id` integer.
