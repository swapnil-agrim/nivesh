### Owner decisions resolved here (safest option; recorded in ADR-0011; sign-off issue = Deferred X9)
- **OD-1 Constituents = owner-supplied file, no live fetch.** `nivesh universe load --index NAME --file PATH [--as-of DATE]` ingests a CSV (columns `symbol`, optional `isin`, optional `sector`) offline; parsers are pure functions over small synthetic fixtures. Membership resolves to `security_id` via `SecurityMaster` (ISIN first, symbol alias second); **unresolved rows are reported with count and symbols, never dropped silently**. Index names are config-defined (`universe.indices`), so Smallcap 250 and Russell 1000 work with an owner file but no list is bundled.
- **OD-2 Empty universe raises.** An index with no loaded members, or a universe that is empty after filters, raises `NiveshError("no members loaded for NIFTY500; run `nivesh universe load`")`. **Never falls back to "all stored bars"** (that silently widens). The explicit-id path (`--security`) is kept byte-identical (BR-1, goldens in `test_screen.py`).
- **OD-3 Staleness is a warning, not a failure**: membership `as_of` older than `universe.max_age_days` (default 35) prints a warning in `universe show` and `ideas`.
- **OD-4 Liquidity floor** (`universe.liquidity`): `IN.min_adv_crore = 5` (crore = 10^7 INR, explicit unit field), `US.min_adv_usd_m = 20` (USD 10^6), window `risk.adv_days` (20). Compared in the bar currency (USD floor before FX). **Boundary: ADV exactly at the floor passes (>=).** Fewer than 20 volume bars, stale bars (older than `universe.max_bar_age_days`, default 7 calendar days vs `as_of`) or missing volume = excluded with reason `insufficient liquidity data`, never guessed.
- **OD-5 Exclusions match sector too (TD-1)**: the shared `_matches_exclusion` helper extends to casefolded `security.sector` equality; the risk veto path (`risk_facts`) uses the same helper so both stay consistent. Fund AMFI-code non-match test stays. `config/profile.yaml` gets a comment only.
- **OD-6 Market cap = existing close x `shares_out` only (BR-7, TD-4).** New registry metric `market_cap` (+ bucket label through `analysis.xray.market_cap` bands, "unclassified" when bands are unset). Missing `shares_out` = unavailable with reason `no shares_out filed`, never zero. An external source (#72 remainder) is deferred (X3). Presets do not require cap; the shortlist labels it.
- **OD-7 Presets are pure YAML** in `config/screens/` using only existing metrics (`roce, roe, revenue_cagr, eps_cagr, pe, valuation_percentile, revisions, hard_flag_count, setup_type, base_breakout, pullback_to_50dma, rs_percentile, price_vs_sma200_pct, market_cap`). Threshold values are owner-tunable starting points labelled "example thresholds, not advice". **BR-12 lint**: any rule on a metric whose name starts with `roc_`, `rs_`, `price_vs_` or is `base_breakout`/`pullback_to_50dma`/`setup_type` must co-occur in the same preset with at least one `required` rule on a fundamentals metric (bundles `fa`, `valuation`, `estimates`). Lint reads the registry bundle of each metric (no hard-coded name list beyond the technical prefixes).
- **OD-8 Shortlist** (`ideas.shortlist_size = 8`, hard `ideas.shortlist_max = 12`, `ideas.sector_cap = 2`, `ideas.default_n = 5`): rank by composite desc, tiebreak symbol asc; missing sector bucket = `unclassified`, capped like any sector; held securities are **labelled ADD candidates and kept** by default (`ideas.held = "label"`; `"exclude"` also supported). Config larger than `shortlist_max` is a validation error (cost fan-out cap, risk 3). With `both`, each market gets its own shortlist (<= 2 x max) and one run.
- **OD-9 Minimal ledger (BR-13)**: `ledger_entry` table, append-only via `BEFORE UPDATE` and `BEFORE DELETE` triggers that RAISE; corrections are new rows with `corrects_id`. Row = exactly the ST-12.1 field list (run id, security id, verdict, horizon, conviction, suggested weight, entry zone low/high, invalidation, review date, last close, benchmark level (nullable, reason), input hash, prompt/model versions) plus `reported` (0/1), `preset`, `created_at`. **All committee verdicts on the shortlist are recorded**, `reported=1` only for the top n. Scoring, scorecard, `nivesh-memory` stay with E12 (X5).
- **OD-10 `/ideas` ranking and qualification**: qualify = verdict in {BUY, ACCUMULATE}; rank by conviction (`Confidence` order high > medium > low) then composite desc then symbol asc. Fewer than n qualifying prints "only k of n ideas qualified; no padding". The command never overrides the committee verdict (`committee_rules` cap/veto stays authoritative); vetoed verdicts never qualify. Tier `deep` per ST-9.4; the cost gate may refuse deep (only `deep` is refused, `quick` warns, refinement 4) -> exit 1 with message.
- **OD-11 Watchlist (ST-9.5)**: `watch` table (`security_id` unique, `entry_low`/`entry_high` nullable Decimal-as-text, `added_on`, `note` not stored). Latest verdict = newest ledger row for the security (none = "no verdict yet"). Distance = `(last_close - entry_high)/entry_high` in percent when above the zone, `0 (inside zone)` when within, negative when below; reasons when no zone or no close. R2 alerts deferred (X2).
- **OD-12 Plain text and `--json`** output (no ST-10.2 templates, no `.claude/commands` file), same as E8; JSON via `sort_keys=True`, Decimals as exact strings.
