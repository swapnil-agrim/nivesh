## Decisions recorded in ADR-0014 (D-n; deferrals X-n)
- **D1 Entry point**: one idempotent tick, `nivesh schedule run [--now ISO] [--dry-run]`, called every 5 min by cron/systemd/launchd. A job is due when `now >= scheduled instant` for its trading date and no finished `job_run` row exists; overlapping ticks are safe (claim by PK insert in `BEGIN IMMEDIATE`). Jobs are in-process functions `(JobCtx) -> JobResult`, never subprocess or Typer commands.
- **D2 Idempotency** per `(job, trading_date)` (`job_run` PK). A job that ended `ok`, `skipped` or `failed` (after retries) is not re-run that date; `running` rows older than `stale_running_minutes` (default 60) are reclaimed once (crash recovery) and counted as an attempt.
- **D3 Retries/backoff (NFR-12)**: 3 attempts total (initial + 2 retries), waits 30s then 120s from `schedule.yaml` (`retries: 2`, `backoff_s: [30, 120]`) via injected `sleep`. Final at once (no retry): `BudgetRefused` (new, D18; raised by a `cost.gate` pre-check inside the moved `metered_run`, before any run row), `CalendarUnknown`, `SystemExit`/`KeyboardInterrupt` (not caught). Everything else is retryable, including `NiveshError` (which is what `reader()` makes of DuckDB contention: the busy case is classified by the wrapped message "market database in use"/`duckdb` cause and reported with that reason). `typer.Exit` cannot occur (layering). Final failure: one failure notice (`Message("nivesh job failed: <job>", ...)`) via notifier; reason = `type(e).__name__` + curated text through `redact_text`, then `blocked_reason`/`scan_text` still gates the channel. `notified=1` only if the notifier returned at least one `Outcome` with status `sent`; `send_message` never raises and returns `[]` when no channel is configured, which is recorded as `notified=0` plus reason "no channel configured" (distinct from "send failed") and shown in `schedule status`. If the notifier raises anyway the row still records `failed` plus `notified=0`. A job that ended `failed` (including all 3 attempts hitting a busy DuckDB writer) is final for that date: no later-tick retry (keeps D2 simple); the notice says "market database in use"; no manual re-run flag ships (a fresh trading date runs normally).
- **D4 Calendar (NFR-19)**: NSE (also BSE; no separate calendar) from `calendar_for("IN", settings)`, NYSE rule-computed. `CalendarUnknown` for the year -> job is `skipped` with reason, **one** notice per (job, date) ("NSE holiday list for <year> incomplete, owner action"), no weekday guessing for *scheduling*. The 2026 list is known to be partial (5 dates): `schedule status` prints a warning "NSE holiday list has only N dates for <year>; India jobs may run on an unlisted holiday" whenever N < `min_holidays_warn` (default 8, in `ScheduleSettings`), and the PR/ADR say so plainly (R-2). Each security uses the calendar of its own `security.market` (IN -> NSE, US -> NYSE). Jobs carry `market` (IN|US|none) and `trading_days_only`. Brief IN/nudge/monitors/kill: true; reviews, rescore, backup: false (Saturday).
- **D5 Grace/late**: each job has `grace_minutes` (default 30; brief 30 so "delivered by 08:30" is observable). A due job still runs after the grace window but is stored `late=1` and `schedule status` prints LATE. A job more than `catchup_hours` (default 12) past its instant is `skipped` reason "missed window" rather than run (a laptop waking at night must not send the 08:00 brief at 22:00). Weekly/monthly jobs: window = the whole trading date.
- **D6 US pre-open** (B4, no `zoneinfo`/`tzdata`): `us_is_dst(day)` is computed by rule in `nivesh_engine/schedule.py`: US DST runs from the second Sunday of March (02:00 local) to the first Sunday of November (02:00 local), via the same `_nth_weekday` style as `calendar.py` (reuse it; import from `nivesh_engine.calendar` if public, else a 3-line copy). Job instant = 09:30 New York on the NYSE session day, i.e. 13:30 UTC in EDT or 14:30 UTC in EST, minus `us_lead_min` (default 30), shown in IST: 18:30 IST in EDT (open 19:00 IST) and 19:30 IST in EST (open 20:00 IST). The session open (09:30) is after the 02:00 switch, so the day-of-switch rule is simply `day >= second Sunday of March` and `day < first Sunday of November`. The PID "18:30 IST" is the EDT figure; the yaml `at` for `brief_us` is informational and the computed instant wins (ADR). Rule limited to years >= 2007 (current US law); earlier raises `ValueError` (never reached). Tested on 2026-03-07/08/09 and 2026-10-31/11-01/02 plus 2027 boundaries. Trading date = the NYSE session date.
- **D7 Reviews, narrowed** (open Q3, B2): no new portfolio/rebalance service is built. `weekly_review` (Sat 09:00 IST) = per-holding reviews through a new extracted service `review_service.run_holding_reviews(settings, profile, day, only=None, clock=None) -> HoldingReviewsOutcome(items, reviews, run_id, missing, price_dates)` (P17a: the body of `holdings_cmd` lines ~188-250, i.e. `held_securities`, `active_theses`, `xray_report` once, `review_facts`, `load_bars`, `metered_run` (tier quick, cost gate applies), `asyncio.run(review_all)`, `_record_reviews` ledger rows; `_record_reviews` moves with it and its `typer.echo` warning becomes a returned warning string). Run row command stays `review holdings` (no new command name; the research dossier's `review-portfolio` name is dropped). The saved artefact is the per-holding review files already written by the run plus a minimal deterministic text summary saved via `save_report` (title "Weekly holdings review", one line per holding: symbol, action, reason; no quantities or values) **only if** `save_report` accepts that without `PortfolioInput`; otherwise just the run directory and the `job_run.reason` summary line "N reviewed, M without thesis". The rebalance leg and the `portfolio_review` report (no caller, needs `PortfolioInput`) are deferred (X8). `monthly_fund_review` (first Saturday 09:00) = `mf_report.run_doctor(...)` for held MF schemes, summary line saved in `job_run.reason` and the run directory (no `fund_doctor` report finalize; deferred X8). - **D8 Numeric invalidation level** (open Q2; no price metric exists in the registry): 0009 adds append-only `invalidation_level(id, security_id, level TEXT Decimal, set_on, note)`; latest row per security wins; set via `nivesh schedule invalidation SYMBOL LEVEL [--note]` (owner-supplied, scanned with `scan_text`). Rule `close_below_invalidation` fires on EOD close < level; no level -> the security is listed under `schedule status` "monitors skipped: no numeric invalidation" (never an error, never a guess from `entry_low`). **The invalidation rule does nothing until the owner sets levels**; the PR text and ADR say so plainly. Thesis kill criteria are evaluated by their own nightly job (D12).
- **D9 Monitors are EOD** from stored bars (`load_bars`) of the held securities of **both markets**: the `monitors` job is registered per market (`monitors` IN 17:30 IST on NSE sessions; `monitors_us` 05:30 IST next morning for the previous NYSE session, `enabled: false` by default like `brief_us`), each handling only securities whose `security.market` matches and using that market's calendar. Big move: **one definition**: `closes[-1]` is today's close, `r_today = closes[-1]/closes[-2] - 1`; baseline = `stdev` of the 20 simple returns *before* today (`closes[-22]..closes[-2]`), so **22 closes are required** (fewer -> `None`, reported "not enough history"); fires when `abs(r_today) > vol_mult` (2.5) x baseline stdev (strict; zero baseline -> `None`). Test boundary: 21 closes -> None, 22 closes fires/does not at exactly 2.5 x. 52-week break = close above 252-session high (or below low) on volume > `breakout_volume_mult` (1.5, `analysis.ta`) x 20-day average; watch zone = close inside `[entry_low, entry_high]` of `watched()` on the latest session when the previous session's close was outside it (entry, not "stays in", so #97 fires once per entry). Intraday LTP deferred (X2).
- **D10 Alert contents (ST-11.4)**: `payload` JSON `{what, verdict, next_step, levels}`; verdict = `latest_call` verdict string or "no verdict yet"; next_step is a fixed template per rule ("run nivesh research SYMBOL", "review the thesis"). Text carries symbol, verdict and percentages only: never quantities, values, or 9-18 digit runs. `scan_text` runs on every outgoing alert/digest; a finding blocks the channel but the alert is still stored (`delivered=0`, `blocked` reason in payload).
- **D11 Hygiene (ST-11.7)**: dedupe key `(rule, security_id)`: at most one fired alert per 5 **sessions** of the security's market (`security.market` -> NSE or NYSE calendar; sessions, not days); the history for dedupe counts only **non-suppressed** alerts (a suppressed alert never extends the window); suppressed ones are stored with `delivered=0` and `payload.suppressed="dedupe"`. Session counting never raises: on `CalendarUnknown` (NSE list has no 2027 entry) it falls back to weekday count and tags `payload.note="weekday fallback"`. Digest: when more than 3 alerts are deliverable inside one rolling hour, they go out as one digest message (`delivered=2`, shared `digest_id`). Daily cap `alerts.daily_cap` (default 8, IST date): extras stored with `suppressed="cap"`. The "N held back yesterday" line is prepended to the first alert message of the next IST day; if no alert fires that day, the monitors job sends **one** small message "N alerts held back yesterday" at the end of its run (once per IST date, only when N > 0 and the job ran). - R-4 **Unattended cost**: weekly review is metered; cap refusal (`BudgetRefused`) is final and notified once; the 240 min stale window prevents a double spend (D19). Defaults ship `weekly_review` enabled only because the cost gate holds; the owner can disable in `schedule.yaml`.
