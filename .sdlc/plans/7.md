### Decisions
1. **Currency in the schema (research D-A, resolved)**. Migration `sqlite/0005_us_holdings.sql` (forward-only): rebuild `holding_snapshot` as `holding_snapshot_new` (same columns and ids copied) with `currency TEXT NOT NULL DEFAULT 'INR'` added and `value_inr TEXT` **nullable**; `DROP TABLE holding_snapshot; ALTER TABLE ... RENAME TO holding_snapshot;` and recreate `holding_snapshot_ingest`. Existing rows keep every value and read as `INR` (the E2 behaviour is unchanged; proved by `test_sqlite_0005_upgrades_v4_db_keeping_snapshots_as_inr` and the unchanged E2 test files). **Storage rule**: INR rows store `value_inr` as today; **non-INR rows store `value_inr = NULL`** and native `quantity`/`price`/`avg_cost` (USD). INR is always derived at read time by `nivesh_engine/fx.py` from the `usdinr` macro series for the valuation date, so there is one source of truth and a missing rate is representable ("unavailable", never zero, never `usd_inr` config, never a rate of 1). Import therefore does not need DuckDB or a rate.
2. **Models (additive, E2 callers keep working)**. `Holding` gains `currency: str = "INR"`; `value_inr: Decimal | None`; a `model_validator` requires `value_inr` when `currency == "INR"`; helper property `value_native = quantity * price`. `Txn` gains `currency: str = "INR"` (MF-only table; the `txn` table is not changed and `_save_txns` raises if a non-INR txn is passed). `Source` gains `"alpaca"` and `"us_csv"`; `PRECEDENCE = ("investright", "cas_demat", "cas_rta", "alpaca", "us_csv", "csv")` (a broker-pulled row with a market price outranks a book-value CSV). New frozen `Lot(isin|None, symbol, exchange, currency, holder_ref, acquired_on: date, quantity, cost_per_unit, source, source_label, security_id: int | None = None)`; `IngestReport` gains `lots: int = 0`.
3. **Lots (research D-B) and accounts**. New `lot` table in the same 0005 file: `lot(id INTEGER PRIMARY KEY, ingest_id NOT NULL REFERENCES ingest(id), account_id NOT NULL REFERENCES account(id), security_id NOT NULL REFERENCES security(id), holder_ref TEXT NOT NULL DEFAULT '', acquired_on TEXT NOT NULL, quantity TEXT NOT NULL, cost_per_unit TEXT NOT NULL, currency TEXT NOT NULL)` + index on `ingest_id`. `txn` is not reused (typed purchase/redemption, dedup index, no currency). Lots belong to an ingest and follow the same "newest ingest per (account, holder_ref)" latest-view rule as snapshots, so re-importing an edited file replaces its lots and re-importing the identical file is skipped by the existing digest rule (R-9). One CSV row = one `Holding` row (as E2) plus one `Lot` when the row has `acquired_on`; consolidation already sums same-source same-key rows. `ACCOUNT_KIND`: `alpaca -> "alpaca"`, `us_csv -> "manual_us"` (distinct kinds so a US account can never supersede an India account of the same label); `DEFAULT_ACCOUNT["alpaca"] = "Alpaca"`; the `kind == "csv"` holder block in `save_ingest` becomes `kind in ("csv", "us_csv")`. `upsert_security` writes `currency = h.currency` and `market = 'US'` for USD (else the column default `'IN'`).
4. **US security resolution (BR-6)**. `SecurityResolver`/`Resolved` stay byte-compatible. New `UsSymbolResolver(conn)` in `nivesh_core/security_resolver.py` with `resolve_symbol(symbol, exchange_hint="") -> Resolved | None` over `security WHERE market='US' AND unresolved=0` (case-insensitive symbol; when several exchanges hold the symbol the hint picks one, else `None`, never a guess). The **master's exchange wins** over the CSV's (stable consolidation key, TD-4). With no master row the CSV `exchange` must normalise (via `US_EXCHANGE_ALIASES`) to NYSE, NASDAQ or ARCA, else a line-numbered error that names the fix (`exchange` column or `nivesh master build`). `US_EXCHANGE_ALIASES` (`NYSE, NASDAQ, ARCA, NYSE ARCA, NYSEARCA, AMEX, NYSE AMERICAN` -> `NYSE|NASDAQ|ARCA`; AMEX and NYSE American map to NYSE) lives in `security_resolver.py` and is imported by `master_sources.SEC_EXCHANGES` (adds ARCA spellings). A master row on CBOE/OTC is rejected for import ("not NYSE/NASDAQ/ARCA"). Consolidation key for a non-INR row without ISIN is `symbol:CURRENCY` (e.g. `AAPL:USD`) so the same ticker from different sources dedupes whatever exchange label each carried.
5. **FX engine (ST-3.3)**. Pure `nivesh_engine/fx.py`, Decimal only: `FxResult(rate: Decimal | None, rate_date: date | None, source: str, stale: bool, reason: str | None)` with `available` property; `rate_on_or_before(obs: Sequence[tuple[date, Decimal]], on: date, source: str, *, stale_days=5, max_age_days: int | None = None) -> FxResult` (latest observation on or before `on`; non-positive values ignored; none -> `reason="no USDINR observation on or before <date>"`; older than `max_age_days` -> unavailable with reason, used for lot dates; older than `stale_days` -> available with `stale=True`, used for valuation); `convert_holdings(holdings, fx) -> list[Holding]` fills `value_inr = quantity*price*rate` for non-INR rows only when `fx.available`, otherwise leaves `None`. `source` text is honest: `"<spec.source>:<spec.id> (RBI reference rate not wired)"`, e.g. `fred:DEXINUS (RBI reference rate not wired)`. The PID's "RBI reference rate (FRED fallback)" is satisfied by the FRED leg only; the RBI leg is deferred (D1). The valuation date in MCP tools is the IST date of the injectable clock.
6. **Consolidation + exposure (ST-3.3 AC2)**. `consolidate(holdings, scope_ref=None, fx=None)` first applies `convert_holdings`; `Row` gains `currency`, `value_native: Decimal | None` (set for non-INR), `value_inr: Decimal | None`, `weight: Decimal | None`; totals, weights, coverage and `invested`/`pnl` use only rows with an INR value; USD cost is converted at the valuation-date rate (so INR P&L excludes FX gain on cost, stated in a note; historical-rate P&L deferred D6); `Consolidated` gains `fx: FxResult | None` (None when no non-INR row) and `exposure: list[Exposure]` (`currency`, `value_inr`, `value_native`, `pct`, `available`): INR share vs USD share of the portfolio, `pct=None` and `available=False` for USD when the rate is missing, plus a note naming how many USD holdings are excluded and why. **E2 bug avoided**: `_merge` computes `price = value_inr / qty`; for a non-INR key it must keep the native price (`sum(qty*price)/qty`), tested (R-2). Rows sort by INR value descending, unavailable rows last.
7. **XIRR scope (research D-C, decided: IN scope, minimal)**. `nivesh_engine/returns.py`: `xirr(flows) -> Decimal | None`, Decimal bisection on `NPV(r)=sum(cf/(1+r)^(days/365))`, bracket `(-0.999999, 100)`, returns `None` for fewer than two flows, no sign change, all flows on one date, or no root in the bracket (never raises, never 0). A thin `lot_report(...)` composes per-lot holding period and per-security and portfolio USD XIRR (S6a) and INR XIRR (S6b). Terminal value = lot quantity x the latest stored US close on or before the valuation date from DuckDB `price_bar` (E4 `get_bars`), accepted only if at most 10 days old; otherwise USD XIRR for that security is `unavailable` with reason "no recent stored price" (CSV rows carry cost only). INR XIRR converts each lot cost at the `usdinr` observation on or before the lot date (cap `max_age_days=7`) and the terminal value at the valuation-date rate; any missing rate makes INR XIRR unavailable with the reason while USD XIRR is still shown. Portfolio-level XIRR is computed only when every USD security has a price (else unavailable, naming which); never partial. Alpaca rows have no lot dates (positions endpoint is aggregate), so they report "no lot dates" (D4). If the loop trims scope, S6b is the first cut.
8. **Holding period and tax parameters (ST-3.4 AC2)**. `holding_days = (valuation_date - acquired_on).days`. New config `tax: TaxSettings(us_long_term_days: int | None = None, gt 0)` (`extra=forbid`). The sample `config/nivesh.yaml` sets it with the comment "owner-set parameter, example only; Nivesh gives no tax advice". Output `long_term: bool | None` is `None` when unset and carries the label "parameter from config, informational"; no tax amounts or advice text anywhere (asserted by a docstring/word test).
9. **MCP surface (extend, one new tool)**. `get_holdings` and `combined_portfolio` rows gain `currency`, `value_usd` (non-INR native value), `value_inr` (null when unavailable), totals gain `value_usd`, `unavailable_count`, a top-level `fx` block (`available, fx_rate, fx_date, fx_source, stale, reason`) and `exposure` (`currency, exposure_pct, value_inr, value_usd, available`); `source` accepts `alpaca`/`us_csv` via `PRECEDENCE`. One new tool `get_lots(symbol=None, limit=200, cursor=0)` (lots with `acquired_on`, `holding_days`, `long_term`, per-security `xirr_usd`, `xirr_inr`, `price`, `price_date`, reasons). The FX/price reads open DuckDB **read-only** after `_db()` ran `init_stores` (E4 decision 12 semantics); a lock error becomes "unavailable, market data busy", never a crash and never zero. Redaction-safe names only (`value_usd, fx_rate, fx_date, fx_source, acquired_on, holding_days, xirr_usd, xirr_inr, exposure_pct`); JSON numbers, no digit-run strings; no `key|client|account|token|address` parts. `asset_id`, `id`, `account_number` from Alpaca never reach any payload. Docstrings avoid inflected write verbs ("acquired", "bought" is not used; say "lots", "acquisition date"); the tool-count tests move to 8 and `.claude/settings.json` gains `mcp__holdings__get_lots`.
10. **Broker connector and proxy (ST-3.2; D-E, D-F)**. `nivesh_adapters/alpaca.py`: `BrokerReader` Protocol (`positions()`, `account()`), `AlpacaClient(Adapter)` (`name="alpaca"`) with only `positions()` and `account()` (`GET /v2/positions`, `GET /v2/account`; fields per spec, unverified). Credentials are config refs (`us_broker.alpaca_key`, `us_broker.alpaca_secret`, secrets `ALPACA_KEY`, `ALPACA_SECRET`); the two header names and every dummy value are built by concatenation (`"APCA-API-" + "KEY-ID"`, `"APCA-API-" + "SECRET-KEY"`), mirroring `investright.py` two-step headers. `account()` returns a whitelisted subset (`currency, status, cash, equity`) so `account_number`/`id` are dropped at the adapter boundary; `positions()` rows are whitelisted to `symbol, exchange, qty, avg_entry_price, current_price, asset_class` (drops `asset_id`). `normalise_positions` maps to `Holding(currency="USD", source="alpaca", price_basis="ltp"|"avg_cost", value_inr=None)`, skips short/zero positions and unsupported exchanges with a warning in the ingest report. `nivesh_adapters/broker_proxy.py`: `ToolCaller` Protocol (`list_tools() -> list[dict]`, `call_tool(name, args) -> Any`) and `ReadOnlyProxy(upstream, allow)`; construction rejects an empty allow-list and any name for which `is_write_name` is true; `list_tools()` returns only upstream tools whose name is in `allow`; `call_tool` raises `ProxyDenied(NiveshError)` for anything else without echoing arguments. An allow-list (not a block-list) is the control: names the word check cannot see (e.g. `close_position`) are still denied unless explicitly allowed. Shipped as a library + tests; a runnable stdio proxy server is deferred (D2). Robinhood: CSV-export preset only (D-F), no connector.
11. **CSV import (ST-3.1)**. New `nivesh_adapters/csv_import_us.py` (E2's `csv_import.py` stays byte-identical so no E2 test changes): columns `account_label, symbol, exchange, quantity, avg_cost, currency, asset_class, acquired_on` (`templates/holdings_us.csv`, documentation copy). Validation, all collected with 1-based line numbers, all-or-nothing in the CLI: `account_label` non-empty; `symbol` matches `^[A-Z][A-Z0-9.\-]{0,9}$` after upper-casing; `quantity` Decimal > 0 (fractions allowed); `avg_cost` Decimal >= 0 and required; `currency` empty or `USD` else "only USD is supported here"; `asset_class` in `{equity, etf}`; `acquired_on` empty or `YYYY-MM-DD` / `MM/DD/YYYY`, not after `as_of`; exchange per decision 4. Presets `alpaca` and `robinhood` (table-driven candidate headers like E2; `convert_us_preset` emits template text, keeping line numbers aligned, with per-preset constants `currency=USD`, `asset_class=equity`, exchange from the export when a column maps): alpaca `symbol; qty|quantity; avg_entry_price|average entry price; exchange; acquired_on|date acquired`, robinhood `symbol|instrument; quantity|shares; average cost|average buy price|avg cost; date acquired|acquired date|acquired`. Header names are "as documented, unverified against a real export" (Q-1 open). `price` = `avg_cost` with `price_basis="avg_cost"` (book value, no market price), exactly as E2; the consolidation note about book-value rows already covers it. CLI `nivesh import-csv PATH --market in|us` (default `in`, E2 behaviour unchanged), `--preset` validated against the market's presets, `kind="us_csv"`, digest dedupe on `("us_csv", digest)`, `source_label=digest[:8]`.
12. **Secrets, test literals and PII**. All dummies via concatenation builders appended to `tests/pii_values.py`: `alpaca_key_value()`, `alpaca_secret_value()` (short, non-key-shaped, e.g. `"test-" + "alpaca-" + "id"`; never `PK`/`AK`-shaped or 20+ char alphanumeric), `alpaca_key_header()`, `alpaca_secret_header()`. Ingest `source_label` is the 8-hex digest prefix (at most 8 digits, below the 9-digit redaction run).

## Risks / post-ship notes
- Wire formats (Alpaca fields, Alpaca/Robinhood header names, SEC exchange labels for ARCA/AMEX) are spec/doc-inferred and unverified (D3); a wrong guess fails loudly (line-numbered CSV error, `DataQualityError`), never silently.
- FX source is FRED DEXINUS (Fed H.10), not the RBI reference rate (D1); every payload says so. FRED lags a day or two, handled by on-or-before plus a stale flag; a fresh install has no `usdinr` data until `nivesh market macro` runs, so USD INR values read "unavailable" until then (by design, never zero).
- XIRR depends on stored US prices (E4) and CSV lot dates; absent either, it is reported unavailable with the reason. Raw closes versus lot quantities can disagree across a split (D6). INR XIRR needs a rate within 7 days of every lot date, which requires macro history back to the oldest lot; an owner with 5-year-old lots must backfill `usdinr`.
- CSV rows are book value (price = average cost), so USD "value" and P&L from a CSV are cost, not market; the existing consolidation note covers it. Alpaca rows carry `current_price` and are market-valued.
- Consolidation keys non-INR no-ISIN rows as `symbol:USD`; two US companies reusing a ticker across time are indistinguishable (rare; ISIN, when present, wins).
- Table rebuild in 0005 holds the SQLite write lock only for the migration transaction; E2 data volumes are tiny. `nivesh backup` before upgrade is the documented safeguard.
- The proxy cannot know a tool is dangerous; the owner-reviewed allow-list is the control. Allowing a tool whose name is innocuous but acts (e.g. `close_position`) is an owner error the word check cannot catch; construction only rejects names that are write words.
- Read-time DuckDB open from the holdings server relies on E4's `init_stores` skip-when-current semantics; during a long market ingest the FX/price reads degrade to "unavailable (market data busy)" rather than failing the whole tool.
