## Scope and decisions
- Single unit, one PR. Read-only (NFR-1): adapters are GET only; no write verb in any function, class, CLI command name, docstring or enum member used as a callable name (`SWITCH_TO_DIRECT` is a data enum value, not a method). Fixtures only: no network, no real holdings, no PII, no key. Wire formats of MFapi.in, AMFI NAVAll (beyond the E4 fixture grammar) and the monthly-holdings source are "per spec, unverified against live API" (E2/E4/E3 convention); parsers are strict (`DataQualityError`) so a wrong guess fails loudly. Live checks would be `@pytest.mark.live`, skipped in CI, deferred (D3).
- **Every step ends with a full `make check` green.** **No step commits or stages**; the orchestrator commits once.
- **Ordering: core ACs first.** M1 foundation (ADR-0007, migration, models, store, config, `by_amfi_code`), M2 ST-5.1 (AC1), M3 ST-5.2 (AC2), M4 ST-5.3 (AC3), M5 ST-5.4 returns and risk (AC4 first half), M6 ST-5.5 overlap and look-through (AC5), M7 ST-5.6 lots, cost and fund doctor with the BR-12 test (AC6), M8 ST-5.4 valuation lens (AC4 second half), M9 ST-5.7 discovery (AC7), M10 safety, docs, final gate. **Explicit cut order if scope must be trimmed**: (1) M9 (ST-5.7; `nivesh mf discover` goes to D5), (2) M8 (valuation lens; the doctor's valuation-stretch reason then reports "unavailable"), (3) the tax-impact half of M7 (exit load and gain/days remain). M1-M7 alone leave the repo consistent and shippable and satisfy AC1-AC3, AC5, AC6 and the first half of AC4. A trimmed item is moved to Deferred below and recorded in README and ADR, never silently dropped.
- Ponytail: no new dependency (`pyproject.toml`, `uv.lock` untouched, asserted by `git diff --stat`; numpy/pandas/scipy are not project deps, math is Decimal-only like `returns.py`), no new MCP server, no `.mcp.json` or `.claude/settings.json` change (D-I), no registry or base class for one implementation, engine functions take `as_of` and never read the clock, no `random`, no float.
- **Issue #53 (XIRR bracket) stays OUT of scope.** No E5 module calls `xirr` or `lot_report`: holding period uses `returns.holding_days` / `is_long_term` and FIFO gain needs no IRR. `nivesh_engine/returns.py` is not modified; a test (`test_mf_modules_do_not_import_xirr_or_lot_report`, source-text assertion) pins that, so adding a lot-XIRR display later forces the #53 fix (test-first: bracket expansion, +100 percent in 30 days, all-negative flows) in that PR. #53 remains its own P1 follow-up.

### Decisions
1. **ADR-0007** (`docs/adr/0007-mutual-fund-intelligence.md`, written in M1, extended per step): records decisions 2-12, the "price index, not TRI" benchmark label, "wire formats per spec, unverified", IDCW policy, the 3-source precedence, and every deferral D1-D8 by number. `tests/test_adr_0007.py` mirrors `test_adr_0006.py` (needles, deferrals by number, `scan_text(ADR) == []`).
2. **Storage** (`duck/0003_mf.sql`, forward-only, additive, new tables only; DECIMAL, PK includes `source`, UTC text; keyed by the SQLite `security.id` of the MF row, symbol `<ISIN>`, exchange `AMFI`, no cross-store FK, as `price_bar`): `nav_point(security_id, date, nav DECIMAL(18,4) NOT NULL, source, fetched_at, PK(security_id, date, source))`; `fund_meta(security_id, as_of DATE, amfi_code, scheme_name, amc, category, plan, option, expense_ratio DECIMAL(7,4), aum DECIMAL(24,2), benchmark, manager, manager_since DATE, source, PK(security_id, as_of, source))` append-only by `as_of`; `fund_holding(security_id, month_end DATE, isin, weight_pct DECIMAL(9,4), holding_security_id INTEGER NULL, kind, source, PK(security_id, month_end, isin, source))` where `kind` is `equity|other` (cash, derivatives, debt lines stay as `other`, never dropped); `nav_gap(security_id, gap_start, gap_end, missing_days, detected_at, PK(security_id, gap_start))`. Models in new `nivesh_core/mf_models.py` (frozen pydantic: `NavPoint`, `FundMeta`, `FundHoldingRow`, `NavGap`). Helpers in new `nivesh_core/mf_store.py`: `upsert_nav`, `get_nav(conn, sid, start, end)` (oldest first, one value per date by precedence MFapi over AMFI), `last_nav_date`, `write_fund_meta`, `latest_fund_meta(conn, sid, as_of=None)`, `write_fund_holdings`, `get_fund_holdings(conn, sid, month_end)`, `months_stored(conn, sid)`, `write_gaps`, `get_gaps`. Scope limit stated in ADR: only held and candidate schemes are stored (not the 37k-scheme universe).
3. **Config** (`MfSettings`, `extra=forbid`, in `config.py` and the sample `config/nivesh.yaml`, comment "owner-set parameters, example only"): `sources: {nav_primary: "mfapi", nav_fallback: "amfi"}` (Literal), `holdings_source: Literal["mfdata","amc","fixture"]`, `holdings_api_ref: str = "ref:MFDATA_API_KEY"` validated by `REF_RE` (field named `..._ref`, never a key literal; value is a reference only), `nav_gap_days: int = 5` (gt 0), `nav_tolerance: Decimal = 0.005` (cross-source disagreement flag), `consistency: {window_days: [1095, 1826], min_beat_pct: 50, min_median_excess_pct: 0}`, `thresholds: {ter_excess_pct, overlap_pct, downside_capture_max, max_drawdown_pct, min_tenure_years, valuation_stretch_ratio}`, `exit_load: dict[category, {percent, days}]` (owner-set, may be empty), `tax: {long_term_days: int | None, short_rate_pct: Decimal | None, long_rate_pct: Decimal | None}` (unset means gain and days only), `screen: {weights: {consistency, downside, cost, valuation}, universe: list[str]}`, `mar_pct: Decimal = 0` (Sortino minimum acceptable return). No threshold is hard-coded in rules.
4. **ST-5.1 NAV ingestion**. `nivesh_adapters/nav.py`: `MfapiClient(Adapter)` (`name="mfapi"`, `_fetch(amfi_code=...)` GET `/mf/{code}`; JSON `meta` + `data[{date "dd-mm-yyyy", nav}]` newest first) and `AmfiNavAll(Adapter)` (`name="amfi_navall"`, text grammar `code;isin;isin;name;nav;dd-Mon-yyyy`), both via `make_client` + `http_get`; `parse_mfapi`, `parse_navall` return `list[NavPoint]` using `parse_decimal`; reject NAV <= 0, unparsable or future dates, duplicate dates, non-newest-first not assumed (sorted). **Incremental**: MFapi returns full history per call, so `mf_ingest.ingest_nav(duck, sqlite, settings, amfi_code, ..., refresh=False)` fetches through `Run.get(..., "nav")`, keeps only points with `date > last_nav_date` (all points on first run), upserts, and reports `added`, `last_date`, `source`. AMFI NAVAll gives one latest point per scheme, so as fallback it appends a single point per run. **Fallback** only when the primary raises `SourceUnavailable`/`RateLimited` (recorded in `run.failed`); `DataQualityError` from the primary is not masked by the fallback. Cross-source disagreement beyond `nav_tolerance` on the same date writes a flag in the report (E4 `cross_check` style), the primary value wins. **Gap flag**: pure `find_nav_gaps(dates, holidays, limit)` in `mf_ingest.py`: between consecutive stored dates, count weekdays (Mon-Fri) with no point that are not in `market.nse_holidays` (when the year is configured; an unconfigured year does not raise); a run of missing weekdays strictly greater than `nav_gap_days` is a gap (so exactly 5 is not flagged, 6 is); gaps are stored in `nav_gap`, returned as ranges, never filled. Resolution of `amfi_code` to `security_id` goes through `SecurityMaster.by_amfi_code`; an unknown code is an error naming `nivesh master build`.
5. **ST-5.2 metadata and direct twin**. `nivesh_adapters/mf_data.py`: `MfMetaClient(Adapter)` (`name="mf_meta"`, table-driven field map from the source JSON to `FundMeta`, TER as percent, AUM in INR, benchmark as a free-text name, `manager_since` date) and the same module's holdings half (decision 6). Missing TER or AUM is stored as NULL, never 0. Plan and option are normalised to `direct|regular` and `growth|idcw|other` from the scheme name in `fund_meta` (TD-6: `Holding.plan` free text is not trusted alone). New `nivesh_engine/mf_cost.py`: `normalise_scheme(name)` (strip Direct/Regular/Plan/Growth/Option/IDCW/dash tokens, collapse whitespace, case-fold), `resolve_direct_twin(regular, universe) -> TwinResult(status "found"|"ambiguous"|"none", amfi_code, candidates, reason)` matching same AMC + normalised name + `plan == direct` + same option; more than one match returns `ambiguous` with the list, never a guess; `ter_cost(regular, direct, value_inr) -> CostResult(ter_gap_pct, inr_per_year, available, reason)` with `inr_per_year = value_inr * gap / 100`, unavailable (reason names the missing TER, value or twin) when any input is `None`, and a non-positive gap reported as `gap_pct` with `inr_per_year` unavailable "no saving". `SecurityMaster.by_amfi_code(code) -> SecurityRow | None` (growth-option row preferred, deterministic order by `id`) added without changing existing contracts.
6. **ST-5.3 monthly holdings**. Source behind the interface: `MfHoldingsClient(Adapter)` (`name="mf_holdings"`, `holdings_source` config selects the parser table), data type `mf_holdings` (31 d TTL). Parser validates ISIN shape (12 alnum), weight in [0, 100], per-fund-month sum <= 101 (rounding slack), month-end dates; weights above that raise `DataQualityError`. `ingest_holdings` stores the latest N months the source offers (append-only per month; N from the source, not capped to 12), maps each ISIN through `SecurityMaster.resolve` (E4 master) to `holding_security_id`, and reports per fund-month `mapped_pct`, `unmapped_pct` (sum of weights whose ISIN is not in the master; `other` lines such as cash are their own bucket, not "unmapped") and `months_stored`. A coverage line is printed when `months_stored < 12`, so the "at least 12 months" AC is verifiable and a shortfall is visible rather than hidden.
7. **ST-5.4 analytics** (`nivesh_engine/mf_returns.py`, pure, Decimal-only, no I/O, no clock, `with localcontext` fixed precision 28 and `ROUND_HALF_EVEN`, quantised only at the output boundary). Inputs: ascending `(date, nav)` series and a benchmark series from stored index bars (`price_bar`; labelled "price index, not TRI"); `window_days` is a parameter (config defaults 1095 / 1826; tests use short windows plus one real-size test on a formula-generated series). Definitions fixed in the ADR: a window ends on each NAV date `d` with start = the latest NAV on or before `d - window_days` (windows without a start point are skipped; fewer than 2 windows gives "unavailable: insufficient history"); window return = annualised CAGR `(end/start)^(365/window_days) - 1` via `Decimal.ln/exp`; excess = fund window return minus the benchmark window return on the same dates (series aligned on common dates; `coverage_pct` of aligned dates reported; below a minimum alignment the metric is unavailable); `beat_pct` = share of windows with excess > 0; `median_excess` = median (even count averages the two middle values); std dev = sample std dev of daily returns annualised by `sqrt(252)` using `Decimal.sqrt()`; max drawdown on the NAV series (peak-to-trough fraction, with the dates); downside capture = mean fund daily return over days the benchmark fell divided by the mean benchmark return over those days (unavailable if no down days); Sortino = (annualised mean daily return - `mar_pct`) / annualised downside deviation (unavailable if downside deviation is 0 or no data). IDCW-option schemes return `comparable=False, reason="IDCW payouts distort NAV; use the growth option"` rather than numbers (R-8). Every metric is `Decimal | None` plus a `reason`; "unavailable" is never rendered as 0. Valuation lens (`nivesh_engine/mf_valuation.py`, M8): `weighted_multiple(holdings, per_isin_multiple)` = weighted harmonic mean of P/E and P/B over holdings that have a positive multiple (earnings yield aggregation, so negative or missing earnings do not poison the average), `coverage_pct` = weight of holdings with a multiple, unavailable if coverage is below a configured minimum; `history_compare(series_by_month, current)` returns the fund portfolio's current multiple versus the median/min/max of its own trailing 36 month-ends (needs at least 24 usable months, else unavailable with the count). Per-ISIN multiples are inputs (a mapping built by the CLI from stored fundamentals and bars via E4 `ratios`/`get_bars` as of each month end); the engine never reads stores.
8. **ST-5.5 overlap and look-through** (`nivesh_engine/mf_overlap.py`, pure). `pairwise_overlap(a, b)` = sum over common ISINs of `min(weight_a, weight_b)` in percent; `overlap_matrix(funds)` is symmetric with a deterministic order (sorted by amfi_code), diagonal omitted; `look_through(rows, fund_holdings, sector_of, direct_rows, total)` combines for each owned fund `value_inr * weight_pct / 100` per ISIN with direct-equity rows (same ISIN sums, so a stock held directly and via two funds appears once with all three contributions listed), returns per stock and per sector `exposure_inr` and `exposure_pct` of portfolio total, top 20 stocks (ties broken by ISIN), an `unmapped_sector_pct` bucket (ISINs whose `security.sector` is NULL are reported, not guessed) and an `other_pct` bucket (cash/debt/derivative lines). A fund whose `value_inr` is `None` is excluded and named in `excluded` with reason; holdings older than the latest stored month are used with their `month_end` shown. Funds that hold other funds are not recursed (R-7 stated in ADR and a test that the nested line lands in `other`).
9. **ST-5.6 lots and fund doctor**. `nivesh_engine/mf_lots.py`: `fifo_lots(txns)` builds open lots per scheme from `Txn` purchases/redemptions (oldest first; redemptions consume oldest lots; negative open balance is a data error reported, not clamped), then per lot `holding_days` (via `returns.holding_days`) and `gain = units * current_nav - cost`; `exit_load_estimate(lots, category, cfg)`: for lots with `holding_days < days` the amount is `lot_value * percent / 100`, and a category with no `mf.exit_load` entry gives `{"available": false, "reason": "exit load unknown (owner-set table has no entry)"}`, never 0; `tax_impact(lots, cfg)`: gain and days always, `long_term` flag via `is_long_term(days, cfg.long_term_days)` (None when unset), tax amount only when the owner has set the rate for that bucket, else unavailable with reason; wording is informational, no advice (asserted by a word test over docstrings and output text). `nivesh_engine/fund_doctor.py`: `ReasonCode` enum and `Action` enum (`KEEP, SWITCH_TO_DIRECT, REPLACE, CONSOLIDATE, REVIEW`); `FundFacts` carries only the metrics (twin status, TER gap, overlap with owned same-category fund, beat_pct, median_excess, downside capture, max drawdown, Sortino, tenure, valuation ratio, `trailing_1y` as display-only); `diagnose(facts, cfg, candidates_available) -> Verdict(action, reasons: list[Reason(code, metric, value, threshold)], exit_load, tax_impact, deferred: list[str])`. Ordered rules (research D-H): (1) regular plan with a found twin and positive TER gap -> SWITCH_TO_DIRECT; (2) overlap above threshold with an owned same-category fund -> CONSOLIDATE; (3) consistency below `min_beat_pct`/median excess, or downside capture/drawdown beyond thresholds -> REPLACE when a screened candidate exists, else REVIEW; (4) manager change within tenure threshold, valuation stretch, or a metric that is unavailable where a rule needs it -> REVIEW (unavailable metrics are listed as `unavailable` reasons, never treated as passing or failing silently); else KEEP. The tie order between rules is the numbered order; ties inside a rule are alphabetical by reason code. `exit_load` and `tax_impact` blocks are computed and placed before `action` in the output for SWITCH_TO_DIRECT and REPLACE only (AC6 "before any SWITCH or REPLACE"). **BR-12 guard**: `trailing_1y` is accepted as input but no rule reads it; a `Verdict` whose only reason cites a 1y return is impossible by construction and asserted by test. The `deferred` list always contains "agent reasoning and /review-funds command (ST-7.5, not built)". The scheme, manager and category strings are untrusted external text: never interpolated into any instruction or prompt in this goal; R-13 noted for ST-7.5.
10. **ST-5.7 discovery** (`nivesh_engine/fund_screen.py`, pure). `screen(candidates, constraints, owned_holdings, weights) -> list[Candidate]` (<= 5): hard filters direct plan, `aum >= min_aum`, `ter <= max_ter`, `manager tenure >= min_tenure` (unknown AUM/TER/tenure excludes the candidate with the reason listed in `rejected`, it is not assumed to pass), IDCW and non-comparable funds excluded; weighted rank-sum over consistency (`beat_pct`, `median_excess`), downside capture, cost (TER), valuation (lower stretch ranks better; `unavailable` ranks last and is flagged), weights from config, deterministic tie-break by `amfi_code`; each result carries `overlap_vs_owned` (max pairwise overlap and with which owned fund) and the metric values behind its rank. The candidate universe (D-F) is schemes with stored NAV + `fund_meta` + `fund_holding` in the requested SEBI category, populated by `nivesh mf nav|meta|holdings` or `mf.screen.universe`.
11. **CLI** (`nivesh_cli/mf.py`, registered in `main.py` as `mf_app`): `nivesh mf nav CODE... [--refresh]`, `meta CODE...`, `holdings CODE...`, `returns CODE [--benchmark ID]`, `overlap`, `doctor`, `discover --category C [--max-ter --min-aum --min-tenure]`. Output prints counts, dates and metric values, no secrets. Reports read the latest holdings (`latest_holdings`) and `consolidate` for `value_inr`; scheme names are shown, folio/holder data never enter MF tables or output (`holder_ref` hashes only).
12. **Secrets, test literals and PII**. MFapi and AMFI need no key. The holdings source key, if any, is `ref:NAME` only. Any credential-looking dummy in a test is built by string concatenation in `tests/pii_values.py` (`mf_source_ref_value()`, plus `mf_param_name()` building the parameter name as `"api_" + "key"`), never a key-like or 20+ char alphanumeric literal; docs describe source wire formats in prose with no sample URL carrying a token. Field names are redaction-safe (ADR-0004): `amfi_code, scheme_name, category, plan, option, expense_ratio, aum, benchmark, manager, manager_since, nav, weight_pct, overlap_pct, exposure_inr, exposure_pct, as_of, source`; none contains `token|secret|password|authorization|cookie|folio|aadhaar|apikey` or the parts `pan|account|acct|key|email|phone|mobile|address|dp|client`. Fixtures use invented ISIN-shaped codes (`INF000A01011` style) and synthetic "Example Mutual Fund" names; no 9+ digit runs (AUM in the fixture is expressed in crore as a small number in the source, converted in the parser; scheme codes are 5-6 digits). `nivesh pii-scan tests/fixtures docs templates README.md config` exits 0 after each step that adds fixtures.
13. **Coverage gate (85 percent, engine + adapters)**. New gated modules: `mf_returns, mf_valuation, mf_overlap, mf_cost, mf_lots, fund_doctor, fund_screen` (engine), `nav.py, mf_data.py, mf_ingest.py` (adapters). Each step writes tests first and each new module must reach >= 90 percent (`uv run pytest --cov=nivesh_engine --cov=nivesh_adapters --cov-report=term-missing -q`), including edge branches (short series, empty window, benchmark missing, no down days). Core/CLI are outside the gate but their tests are mandatory.

## Risks / post-ship notes
- Wire formats (MFapi.in JSON, AMFI NAVAll beyond the fixture, monthly-holdings source, metadata fields) are spec-inferred and unverified (D3); a wrong guess fails loudly (`DataQualityError`), never silently.
- Benchmark returns use price-index bars, not TRI, so excess returns are overstated by the dividend yield; every output says so (D4). Category-relative metrics are unavailable until a dataset exists.
- BR-12 is enforced by construction (no rule reads `trailing_1y`) and by three tests; a future rule that reads it fails `test_doctor_source_does_not_read_trailing_1y`.
- Silent zeros: missing TER, AUM, twin, benchmark, exit-load row, tax rate, history, down days, or sector all produce "unavailable" with a reason; each has a dedicated test.
- Twin matching is name-based; near-duplicate names return `ambiguous`, so the doctor may decline to recommend a switch the owner could make by hand (safe failure).
- The valuation lens is data-hungry (36 month-ends of holdings plus per-stock multiples); with partial data it reports coverage and may be unavailable (M8 is the second cut).
- Gap detection uses weekdays minus configured holidays, so a clustered holiday week may be flagged when the year's holidays are not in config; the threshold is configurable.
- IDCW schemes are reported "not comparable", not adjusted (D8). Fund-of-fund look-through does not recurse.
- Only held and candidate schemes are stored; the screen can only rank schemes the owner has loaded (D8).
- Decimal `ln/exp/sqrt` results depend on the fixed context precision; the determinism test pins output across reruns, and the ADR states the precision.
