### Decisions (resolving research Plan calls (a)-(h) and the unverified items)
1. **Placement (c)**: standard schema models + SQLite repository in `nivesh_core/` (`holdings.py`, `holdings_store.py`, `security_resolver.py`, `holder_ref.py`), shared by all layers. Clients/parsers/importers in `nivesh_adapters/` (flat modules only, so `tests/safety` discovery sees them; CAS and CSV code counts toward the 85% gate). Consolidation/reconciliation in `nivesh_engine/consolidate.py` (pure, deterministic, `Decimal`; first real occupant, makes the gate non-vacuous, stale comment in `pyproject.toml [tool.coverage.report]` is removed). CLI in new `nivesh_cli/holdings.py` (`login`, `sync`, `ingest`, `import-csv` registered on `app` from `main.py` with a 3-line import; `main.py` does not grow). MCP in `nivesh_mcp/holdings.py`, registry key `holdings` (source string `nivesh-holdings`).
2. **Schema (e), migration 0003** (forward-only, no table rebuild): `ALTER TABLE security` add `amfi_code TEXT`, `market TEXT NOT NULL DEFAULT 'IN'`, `unresolved INTEGER NOT NULL DEFAULT 0` (the spec's `asset_type` is the existing `asset_class` column; recorded in ADR-0004); `CREATE UNIQUE INDEX account_kind_name ON account(kind, name)` (`name` is the spec's `label`); new tables `ingest`, `ingest_holder`, `holding_snapshot`, `txn` (not `transaction`, reserved). **TD-2**: an unresolved ISIN is stored as `symbol=<ISIN>, exchange='ISIN', unresolved=1`, which fits `UNIQUE(symbol, exchange)` with no relaxation. Money/quantity columns are `TEXT` holding `Decimal` strings (exact); sums happen in Python. Snapshots are append-only per ingest. `ingest_holder(ingest_id, account_id, holder_ref)` records every demat/folio seen in an ingest (including zero-balance ones), so the "latest view" per `(account_id, holder_ref)` takes the newest `ingest.as_of` (then highest id) containing that pair: a fully redeemed folio disappears after a newer statement, and an older statement ingested late never replaces a newer one. `txn` is deduplicated across overlapping monthly statements by a unique index over `(account_id, security_id, holder_ref, date, type, quantity, amount)` with `holder_ref NOT NULL DEFAULT ''`, written with `INSERT OR IGNORE`.
3. **Redaction collisions (g, BR-6)**: `redact_json` masks any key containing `token|secret|password|folio|aadhaar|apikey|authorization|cookie` or a `_`-part in `{pan, account, acct, key, email, phone, mobile, address, dp, client}`, and any string with a 9-18 digit run at a number edge. We do not touch `redact.py`. Field names used in every payload: `holder_ref`, `source_label`, `isin`, `quantity`, `avg_cost`, `price`, `price_basis`, `value_inr`, `weight`, `as_of`, `source`, `txn_type`, `amfi_code`, `plan`, `session_valid`, `issued_ist_date`. Never: `account_*`, `client_*`, `dp_*`, `folio*`, `key`, `*token*`. Numbers in tool payloads are JSON numbers (floats made at the MCP boundary), never digit-run strings; `redact_json` leaves numerics untouched. `holder_ref` values are letters only (see 4), so they cannot hit any digit/PAN/phone pattern. A test pushes a full `combined_portfolio` payload through the real middleware and asserts the numbers and names are intact.
4. **Folio / demat hash (f)**: `hash_ref(value, salt) = base26 letters (a-z, 12 chars, 56 bits) of HMAC-SHA256(salt, value)`. Letters-only because a hex digest has about a 4 percent chance of containing a 9+ digit run, which the digit sweep would mask. Salt is secret `FOLIO_SALT` via `get_secret` (env then keychain); missing salt raises `SecretNotFound` with a hint to run `nivesh secrets set FOLIO_SALT`. Demat `holder_ref = hash_ref(dp_id + "/" + client_id)`; RTA `holder_ref = hash_ref(folio)`.
5. **PII boundary (NFR-3)**: only `nivesh_adapters/cas.py` imports `casparser`. Its public return type `ParsedStatement` (pydantic, frozen) contains only `Holding`, `Txn`, `as_of`, `kind`, `warnings`, `holder_refs`; no field can carry a name, PAN, email, mobile, address, DP/client ID or folio. Warnings from casparser are passed through `redact_text` and truncated to 200 chars before leaving the layer. Any casparser exception is converted to `CasError` with a fixed message (`IncorrectPasswordError` to "wrong CAS password", anything else to "could not parse statement") and `from None`: casparser exceptions can echo content, and the password never appears in any message.
6. **casparser seam (b)**: `nivesh_adapters/cas.py::_read(path, password)` is the only call into `casparser.read_cas_pdf`; unit tests monkeypatch `_read` (and in one test `casparser.read_cas_pdf`) and construct `casparser.types.CASData` / `NSDLCASData` models directly (importable pydantic models). Dispatch is by `isinstance`. First action of step C3 is to read the installed `casparser` source (return types for `output=`, `statement_period` shape, `Scheme.close` / `close_calculated`, `valuation.cost`, NSDL `accounts[].equities/mutual_funds/bonds`, `parse_warnings`, `IncorrectPasswordError`) and record the facts in the ADR; model field names in the tests follow what is found, not this plan's recollection. One `@pytest.mark.live` test accepts a user-supplied PDF via `NIVESH_CAS_SAMPLE`/`NIVESH_CAS_SAMPLE_PASSWORD` env vars and is skipped in CI.
7. **Login (d)**: stdlib one-shot `http.server` bound to the literal `127.0.0.1` only (constant `CALLBACK_HOST`), default port from settings (8765). Tests never open sockets (conftest blocks `connect`): they cover the pure `parse_callback_path`, `extract_request_token`, the exchange via `httpx.MockTransport`, and a constant check. `nivesh login --paste` reads the pasted URL/token from a hidden prompt; without `--paste` the listener waits up to 120 s. API key/secret come from `get_secret` only, never argv.
8. **IST rollover (h, BR-12)**: `timeutil.ist_date(now)` uses a fixed `timezone(timedelta(hours=5, minutes=30))` (India has no DST), so no `zoneinfo`/`tzdata` dependency. Token file `<data_dir>/investright_session.json` holds `{"session_token": ..., "issued_ist_date": "YYYY-MM-DD"}` written 0600 by a new `replace_private` (temp file via `write_private` after unlinking a stale temp, then `os.replace`; refuses a symlink target). `valid(now)` = file exists and `issued_ist_date == ist_date(now)`; clock is injected. A corrupt file counts as missing.
9. **Price basis / value**: values are `Decimal`, `value_inr = quantity * price`. `price_basis` is one of `previous_close | ltp | nav | statement | avg_cost`. InvestRight: `close_price` only gives `previous_close`, LTP enrichment gives `ltp`. RTA CAS: `nav`. Depository CAS: `statement` (statement-date value / price). CSV has no market price: `price = avg_cost`, basis `avg_cost` (book value, flagged in `combined_portfolio` notes). India-only here, base INR, no FX (E3).
10. **Consolidation rule (E)**: key = ISIN (or `symbol:exchange` when a CSV row has no ISIN). Rows of the same source and key are summed (quantity added, avg_cost quantity-weighted over rows that have cost). Across sources, quantity/price/value come from the highest-precedence source holding that key (InvestRight > depository CAS > RTA CAS > CSV); `avg_cost` comes from the highest-precedence source that has one. Optional config `investright.demat_ref` (a `holder_ref` printed by `nivesh ingest`) scopes the InvestRight-vs-depository overlap to that one demat: when set, depository rows with another `holder_ref` are additional holdings rather than duplicates, and reconciliation compares only that demat; when unset, ISIN-level (literal spec) and a note says so. Ceiling noted in Risks.
11. **Test literals (TD-8)**: the commit secret-scanner refuses credential/PAN/token-looking literals. All dummies come from `tests/pii_values.py` builders using concatenation; this plan adds `request_token()`, `api_secret()`, `salt()`, `holder_name()`, `dp_code()`, `client_code()`, `cas_password()`. No test, fixture, doc or this plan contains a whole PAN-shaped, token-shaped or 10-digit-phone literal. Fixture JSON/CSV files contain no 9+ digit runs and no PII; `nivesh pii-scan tests/fixtures docs templates` must exit 0.
12. **Config (BR-11)**: `Settings.investright: InvestRightSettings(base_url, redirect_port=8765, app_key="ref:INVESTRIGHT_API_KEY", api_secret_field=("ref:INVESTRIGHT_API_SECRET"), user_agent="nivesh/0.1", demat_ref: str|None)`; `extra=forbid`; default block present so existing configs load. Fixed secret names: `CAS_PASSWORD`, `FOLIO_SALT`. Inbox is `<data_dir>/inbox` (no setting). No holdings TTL: live holdings bypass the cache (D7).
13. **Existing tests to adjust (found in the worktree)**: `tests/core/test_migrate.py` hardcodes version 2 (lines ~29, 54, 83, 90) and its `migrations_with_next` helper writes `0003_add_col.sql`, which collides with the real 0003 (make it write `latest_version + 1`); `tests/core/test_init.py:31` expects 2; `tests/agents/test_claude_config.py` and `tests/mcp/test_list.py` derive from `SERVERS` so they pick up `holdings` once `.mcp.json` and `.claude/settings.json` list it (explicit tool names, no wildcards; `enabledMcpjsonServers == ["demo","holdings"]`); `tests/test_layout.py` requires the README to keep the text `investright-mcp`.

## Risks / post-ship notes
- InvestRight wire format (base URL, login URL, request-token parameter, row field names, response shapes) is spec-inferred and unverified (D2); a wrong guess fails loudly (`DataQualityError`/`InvestRightError`), never silently.
- casparser behaviour on real statements is unverified (D3); parse quality depends on a third-party parser. It pulls `pypdfium2` (native wheel) and a 47 MB ISIN db, growing the Docker image by about 60 MB; a pip-audit advisory on it would block CI.
- Consolidation key is the ISIN. Same ISIN across demats covered by different sources is under-counted unless `investright.demat_ref` is set (D9); reconciliation shows the mismatch instead of hiding it.
- "Latest view" depends on `ingest.as_of`; a CAS with a wrong statement date can mask a newer one. Fully emptied InvestRight accounts are handled by the next sync (no rows saved, `ingest_holder` row still written).
- Field-name redaction is blunt; any new payload field containing `key`, `client`, `account`, `folio`, `token` will be masked. Guarded by the middleware survival test.
- Adding the unique index `account(kind, name)` assumes no pre-existing duplicate accounts; `account` is unwritten today, so safe, but sigma-migration-check should confirm.
- The coverage gate (85 percent over engine + adapters) now binds real code; adapters `cas.py` and `csv_import.py` must be tested to that level, not just present.
- `read_cas_statement` parses a PDF with a keychain password on model request; the path restriction and fixed error messages are the control, review under sigma-security-review.
