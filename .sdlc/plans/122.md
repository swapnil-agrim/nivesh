## Design calls (the loop owner's four decisions, confirmed against code; refinements marked R)
1. **Holidays**: built-in `DEFAULT_NSE_HOLIDAYS` (2024-2026) in a new `nivesh_core/nse_holidays.py`; `merged_nse_holidays(configured)` = built-in per year, replaced wholesale by the config entry for any year the config lists. Exposed as `MarketSettings.effective_nse_holidays()` (the raw `nse_holidays` field stays `{}` by default: `tests/core/test_config.py:145` pins that). The three readers use the merged dict: `calendar_for` (`market_ingest.py:136-139`), `_warnings` (`nivesh_cli/schedule.py:100-110`), `_holidays` (`mf_ingest.py:144-145`). `CalendarUnknown` stays for years with no data anywhere (ADR-0014 D4); message names the fix and the built-in range. NYSE: add the 2025-01-09 national day of mourning as a one-off in `nyse_holidays`. Fix Saturday 2026-08-15 in the shipped yaml (weekday lists only). Verified in code: `Calendar._year_holidays` raises for a missing year (`calendar.py:79-86`); config validator only checks year membership (`config.py:150-157`); no layer rule blocks `nivesh_engine` importing `nivesh_core`.
2. **Bhavcopy**: `validate_payload` becomes structural only (header columns, parseable `TradDt`, numeric parse of price/volume cells). No row-level OHLC check. Row-level policy lives only in `parse_bhavcopy`/`parse_indices`: the requested security's bad row stays fatal (`test_negative_or_inverted_ohlc_raises_data_quality_error` unchanged and green); with `audit=True` every other row (any series) is OHLC-checked and a failure is counted by reason in `ParsedBars.bad_rows` instead of raising. `_india` passes `audit=True` and sums into `PriceReport.bad_rows`; `nivesh market prices` prints one line when the total is nonzero. Same rule for the index file. **R-a**: unparseable numeric cell stays fatal (structural, file looks corrupt), only OHLC-rule violations are skippable; verified against the dossier (all 119 live bad rows are series T0 violating `check_ohlc`, none is a parse error). **R-b**: because `parse_bhavcopy` already drops series outside `EQUITY_SERIES` before validating, RELIANCE's own T0 rows (2025-11-21, 2026-04-23) never reach `check_ohlc`; the fatal path for the requested security therefore only fires on its EQ-class rows (correct per issue).
3. **Master build**: AMFI -> `https://portal.amfiindia.com/spages/NAVAll.txt`; redirects followed per call for `nse`, `bse`, `amfi` only (not `sec`: a redirect must never carry the contact User-Agent to another host) and for the AMFI NAV fallback in `nav.py` via `http_get(..., follow_redirects=True)`; `make_client` untouched (no global flag). BSE master derived from the BSE UDiFF bhavcopy (same URL shape as `prices_in.BSE_CSV`), walking back day by day from today over 404s (cap 10 days) to the latest file; parse gives `symbol`=TckrSymb, `name`=FinInstrmNm, `isin`=ISIN, `bse_code`=FinInstrmId (no industry). SEC without `EDGAR_CONTACT`: per-source message "US securities skipped" with the fix, build continues. Summary prints per-source ok/failed with reason; exit 1 only if every source fails (unchanged). Verified: `master_build` already catches per source (`nivesh_cli/market.py:118-128`), so "crash" in the issue is not reproducible; the real defects are URL, redirect and BSE format.
4. **Out of scope, filed as follow-ups with exact errors** (Step E3): `api.bseindia.com` fundamentals HTTP 403 (BR-20), NSE corporate-actions endpoint HTTP 404 swallowed by `http_get` into `[]` (BR-21/TD-5), bhavcopy full-text cache size ~550 KB/day (TD-2). `fa RELIANCE` on live data is expected to report items unavailable; the live run records exactly what and why.

- **R2 Audit parse cost.** `audit=True` checks every row of every day (about 3000 rows x 275 days). Expected seconds; measure in E1, if slow restrict audit to rows failing a cheap pre-check (`ClsPric` outside `[LwPric, HghPric]`).
- **R3 Special weekend sessions (BR-18)** (Muhurat, Sat 2024-01-20 and 05-18) are not representable; weekday-only holidays mean those days are simply not sessions. Documented, not fixed.
- **R4 BSE derived file is large** (~600 KB, cached as one master entry) and its `SctySrs` includes non-equity groups; the filter is decided from live data (E1). A BSE walk-back that lands on a holiday-heavy week is bounded by the 10-day cap and reports a clear failure.
- **R5 NYSE one-offs unverified** beyond 2025-01-09 (no NYSE source fetched); state this in the PR.
- **R6 Holiday data accuracy** is derived from 404 oracles plus the 2026 NSE feed; `gaps: none` in E1 is the cross-check. Years beyond 2026 still raise `CalendarUnknown` by design.
- **R7 Contract-shaped outputs**: `PriceReport` gains a field and two CLI outputs gain lines (additive). `nivesh_mcp` consumers of `PriceReport`/`calendar_for` are unchanged; verify with `rg -n "PriceReport|calendar_for" nivesh_mcp`.
- **R8 Secret/PII scanners** on new fixtures and docs (see Constraints); run `uv run pytest tests/adapters/test_master_sources.py -k pii` and the fixtures scan tests after editing `bse_scrips.csv`.
