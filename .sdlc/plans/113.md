## Design decisions (evidence from the code)
- D1 Location: `S = tests/scan_fx.py`, imported as `from tests.scan_fx import ...`, the same pattern as `from tests import pii_values as pv` and `from tests.ideas_fx import ...` (`tests/`, `tests/cli/`, `tests/security/` all have `__init__.py`; `tests/cli/test_market.py` already imports `tests.*`). Not `tests/security/helpers.py`: `tests/cli/*` importing from `tests.security` is backwards and a second re-export path doubles the surface; the acceptance says "for example". If the orchestrator wants the literal path, a two-line `tests/security/helpers.py` re-export is a trivial add. Import order: rule `I` only (no isort section; `tests` is auto first-party), so `from tests.scan_fx import ...` goes after `tests.run_paths` / `tests.market_fx`; `ruff check --select I --fix <file>` sorts it.
- D2 API, plain functions only (a fixture named `scan_output` would shadow the import and hide the roots): constants `MASK = "<path>"`, `BOUNDARY_MASK = "<boundary>"`, `MIN_ROOT = 8`, `MIN_BOUNDARY = 16`; `mask_roots(*roots) -> list[str]`; `clean_output(text, *roots) -> str`; `scan_output(text, *roots) -> list[Finding]` = `scan_text(clean_output(text, *roots))` (unchanged scanner, same `Finding` list, so every `== []` keeps its meaning); `fix_boundary(body, content_type) -> str`; `request_text(request) -> str`.
- D3 Roots always covered: `tempfile.gettempdir()`, `Path.cwd()` (catch `OSError`), the repo root `Path(__file__).resolve().parents[1]`, plus every explicit `*roots` (`str` or `Path`). Each root expands to a set of forms: as given (trailing `/` stripped), `os.path.realpath`, and the macOS alias both ways (`/var/...` <-> `/private/var/...`, `/tmp/...` <-> `/private/tmp/...`, done by string rule so it is OS independent). Drop forms shorter than `MIN_ROOT` and `/`. Replace with ONE compiled alternation sorted longest-first, with a trailing `(?![A-Za-z0-9_])` so a root only masks itself (`<root>12345` or `<root>x` is another name and is left intact). Exact strings only, never a regex over `/var/folders/...`.
- D3b Why explicit `tmp_path` as well as the auto roots: a poisoned `TMPDIR` (the CI case) is covered by `gettempdir`; a poisoned leaf or `--basetemp` only by the explicit root. So the 18 conversions pass `tmp_path` (17 tests gain a `tmp_path: Path` parameter; `Path` is already imported in every touched file; `cli_env` depends on `tmp_path`, so function-scoped caching hands the test the same object). Rejected: an autouse session fixture registering the basetemp (hidden global state in the shared conftest for about 4000 tests).
- D4 Multipart: `fix_boundary` reads `boundary="?([^";\s]+)` from the content-type header and replaces that exact string (every occurrence) with `BOUNDARY_MASK`, only when it has at least `MIN_BOUNDARY` characters (replacing a short string would rewrite unrelated content); no header or no boundary returns the body unchanged. `request_text(req)` = `fix_boundary(req.content.decode(errors="replace"), req.headers.get("content-type"))`. Framing and file part stay under the scanner. In `test_delivered_payloads_pass_scan_text` only the line `bodies += [calls.requests[1].content.decode(errors="replace")]  # telegram page` changes (to `request_text(calls.requests[1])`); the final `scan_text(str(x).replace(DUMMY_HOOK, ""))` stays raw: temp roots are NOT masked on delivered payloads, because a data-dir path reaching Telegram, Slack or mail would be a real leak.
- D5 Where cleaning happens: a direct `scan_text(X.output)` becomes `scan_output(X.output, tmp_path)`. The four `test_pii_e2e.py` pipeline tests scan a labelled dict of blobs (db, files, mcp are not CLI output), so only the cli blob is cleaned at construction, `"cli": clean_output(<blob>, tmp_path)`, and the loops stay on `scan_text`. Never mask db dumps, files or MCP payloads.
- D6 No digest masking (D§5.2: deterministic per input, three tests already mask ad hoc): follow-up. No product change (D§6).
- D7 Guard G, an AST tripwire, is worth it (parses 274 test files in 0.8 s; a test never needs the raw scan of CLI output, so there is no escape hatch). It flags `scan_text(...)` calls (name or attribute) whose arguments contain an attribute `output`, `stdout` or `stderr`, without descending into `clean_output`, `scan_output` or `request_text` calls. Baseline probe: 16 hits in 13 of the 18 tests; the other 5 (analysis loop, 4 e2e blobs) are invisible to it, stated in its docstring: best-effort, the grep audit and the PR table are the proof. G skips R and itself (their controls call raw `scan_text(r.output)` on purpose).
