## Names and wording rules for the implementer (read before writing any file)
1. **Secret/PII scanner at commit** (`work.py commit` refuses credential-looking literals or identifiers anywhere: code, tests, fixtures, prompts, docs, config). Do not name variables, dict keys, config keys, schema fields, fixture fields or test names `secret`, `token`, `password`, `credential`, `apikey`/`api_key`, `private`, or anything ending `_key` when they hold a string literal. Use `tool_use_id`, `call_id`, `nonce`, `ident`, `pair`. Any dummy string that could look like a credential (a tool-use id, a ref name, a 20+ character alphanumeric run, hex, base64) is **built by concatenation** (`"toolu_" + "0001"`, `"EXAMPLE" + "SERIES"`), never written whole. Decimal literals in tests and fixtures: at most 15 significant digits. Invented ISINs are 12-character strings. No file basename containing `credentials`, `.pem`, `.key`.
2. **Write-word scan** (applies to every new `nivesh_agents/*.py`, `nivesh_engine/committee_rules.py`, `nivesh_adapters/analysis_service.py`, `nivesh_mcp/engine.py`, enforced by the new `tests/safety/test_agent_safety.py`): no function/class name and no docstring word may be one of `place, modify, cancel, transfer, order, buy, sell, delete, withdraw` or their inflections (`ordered`, `orders`, `places`, `placed`, `modified`, `deleted`, `transferred`, `buying`...). In docstrings say "top-band verdict" or "upward verdict", never "BUY"; say "sorted"/"ranked", never "ordered"; say "decimal digits", never "decimal places". The verdict labels exist only as **string data** (a tuple `LADDER = ("BUY", "ACCUMULATE", ...)` is fine; an identifier `BUY`, a function `clamp_buy`, or the docstring "never BUY" is not). Prompts (`.md`) are not AST-scanned, so `tests/agents/test_prompts.py` carries a case-sensitive regex over prompt text banning lowercase write verbs (`place[sd]?|orders?|ordered|modif(y|ied)|cancel|transfer(red|s)?|withdraw|delete[sd]?`); the uppercase labels `BUY`/`SELL` are allowed there as verdict values only.
3. Money, ratios, prices, percentages, weights are `Decimal` in rules and engines; `float` appears only at the boundary in `nivesh_mcp/engine.py` (via `common.num`) and when building SDK options (`max_budget_usd`). `nivesh_engine/committee_rules.py` obeys the E6 source scan (`test_engine_modules_have_no_float_random_or_clock_references`): no `float`, `random`, `datetime.now`, `date.today`, `utcnow`, `time.time` anywhere in the file, comments included. Orchestration time uses an injected `clock` parameter.
4. Dataclasses `frozen=True`; no dict-order or set-iteration dependence in anything written to disk (sort keys, `json.dumps(sort_keys=True)` for digests). File names under the run dir are built only from a fixed enum of agent names, integer ids and a sequence number: never from model output.
5. Model output is data. It is parsed only by the schemas, never evaluated, never used in a path, never put in a shell command, and never passed through `redact_json` (see D-5). Tool results reaching the model are already wrapped for external text by `nivesh_mcp.common.wrap`; every agent's system prompt is `GUARD + prompt text`.
6. Schema field names come from the PID (`key_points`, `tool_call_id`, `evidence`, `stance`, `score`, `weight_pct`, ...) and are kept; avoid new fields named `key`, `account`, `client`, `address`, `email`, `phone`, `token`, `dp`, `pan` (their parts mask under `is_sensitive_key`). Engine payloads over MCP carry Decimals as JSON numbers, keep the CLI renames (`ref`, `overall_vol`), and are audited by a test (BR-21).
7. Pre-empting plan-review refinements raised on plan 9: (a) do NOT edit any existing fixture or existing test other than the five enumerated edits (`tests/mcp/test_list.py`, one function in `tests/safety/test_tool_safety.py`, three spots in `tests/safety/test_analysis_safety.py`); new fixtures get new file names. It identifies the calling agent from a marker the spec puts first in the system prompt (`"[agent:<name>]"` is part of the loaded prompt text), pops the next scripted attempt for that agent (a list of message lists), replays real `AssistantMessage(TextBlock | ToolUseBlock)`, `UserMessage(ToolResultBlock)` and `ResultMessage(structured_output=... | result="json", session_id=...)` objects, and records `seen: list[Call(agent, prompt, options)]`, per-agent call counts, and the peak number of concurrently open generators. Options for raising and for hooks into the call (a callback run at generator start, used by the persistence-order test to inspect the run dir) are parameters. Installed with `monkeypatch.setattr(runtime, "query", fake)`, as in `tests/agents/test_runtime.py`. No network, no model, no PII.

## Conventions fixed here (the ADR records them; tests assert them)
- `AnalystView`: `schema_version=1`, `agent`, `security_id`, `as_of`, `stance` in `bullish|neutral|bearish|insufficient_data`, `score` int 0-100, `confidence` in `low|medium|high`, `thesis` <= 120 words, `key_points[{claim, evidence[{tool_call_id, field, value (number|string), as_of}]}]`, `risks[]`, `data_gaps[]`, optional `levels` (technical only). Cross-field rules: fundamental needs >= 3 key points; `insufficient_data` stance requires non-empty `data_gaps`; every key point has >= 1 evidence item. `extra="forbid"`.
- `MacroView`: `agent="macro"`, `as_of`, `regime` in `risk_on|neutral|risk_off|insufficient_data`, `score`, `confidence`, `thesis`, `key_points`, `sector_tilts[{sector, tilt in overweight|neutral|underweight, evidence}]`, `risks`, `data_gaps`. `FundView`: `agent="mf"`, `scheme` (AMFI code), `stance`, `score`, `confidence`, `thesis`, `key_points`, `cost_note`, `overlap_note`, `category_fit`, `risks`, `data_gaps`.
- `DebateTurn`: `security_id`, `round` (int >= 1; `0` is not allowed, quick summaries use `summary=true` with `round=1`), `side` in `bull|bear`, `claims[{claim, evidence[ref]}]` where `ref` is either `{view: <agent>, point_index: n}` or `{tool_call_id}`, `rebuts[]` (indices into the opponent's previous claims), `strongest_unrebutted`, `summary` bool. `LensView`: `lens` in `value|growth|contrarian|valuation`, `security_id`, `decision` in `would_buy|would_pass` (data strings), `paragraph` <= 150 words, `evidence[ref]`.
- `RiskAssessment`: `security_id`, `veto` (set by code), `veto_reasons[]` (code), `weight_bounds{min_pct, max_pct}` (code), `liquidity_note`, `correlation_note`, `concentration_note`, `risks[]`, `overrides[]` (what code changed in the model's draft). `HoldingReview`: schema + model only (`security_id, as_of, action in keep|add|trim|exit|review, thesis_status in intact|weakened|broken|unknown, kill_criteria_hit[], valuation_stretch, tax_note, evidence[]`); no agent in E7.
- `CommitteeVerdict` (JSON title `Verdict`): the PID 14.5 fields (`security_id, verdict in BUY|ACCUMULATE|HOLD|TRIM|SELL|AVOID|INSUFFICIENT_DATA, horizon in positional_1_6m|long_term_1y_plus, conviction, suggested_weight_pct|null, entry_zone{low, high, ccy}|null, invalidation[], review_date, bull_case, bear_case, risk_notes, vetoed_by_risk`) plus `schema_version`, `as_of`, `coverage_pct`, `overrides[]`. The class is not called `Verdict` because `nivesh_engine/fund_doctor.py` already defines `Verdict`.
- Validation outcome: `Valid(model)` or `Invalid(errors: list[str])` with errors redacted (`redact_text`) and truncated to 2,000 characters before they reach the repair prompt or the trace. Repair prompt = those errors + the sorted list of valid `tool_call_id`s for this agent + "return JSON only"; the repair call uses `resume=<session_id>` when the first result had one (else a fresh query carrying the first output), `allowed_tools=[]`, `mcp_servers={}`, `max_turns=1`. Whether resume with an empty tool list works against the live CLI is **unverified** (offline only; ADR lists it).
- Trace additions (additive; the existing single-run path stays byte-identical): `tool_call(..., agent=None, security_id=None)` and `tool_result(...)` carry the attribution in meta; `agent_start(agent, security_id, model, prompt_version, digest)`; `agent_end(agent, security_id, status, model, in_tok, out_tok, cost_inr, cost_source)` **accumulates** into `totals`; `tool_ids(agent, security_id) -> frozenset[str]` and `all_tool_ids()`; `finish_run(model_label)` sets `summary` (same keys as `result()`) from the totals so `_finish_run` in `nivesh_cli/main.py` is unchanged. `Tracer.result()` keeps replacing, as today.
- Output files: `snapshot.json` = `{run_id, as_of, tier, securities[{security_id, symbol, kind}], profile_limits (Decimal strings), engine_outputs, coverage, prompt_versions, models, config_digest (includes analysis `weights_version` and digest)}`; `outputs/NNN_<agent>_<security_id>.json` = the validated model dump, or `{"status": "failed", "reason": ...}`; a trace record `snapshot_saved` / `output_saved` with a SHA-256 digest each.
