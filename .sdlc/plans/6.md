## Scope and decisions
- Builds on merged E1 + E13 + E2. Read-only only (NFR-1): no write verb in any method, tool name or tool docstring (`ReadOnlyServer` and `tests/safety` enforce it). Fixtures only: no network, no PII, no paid key. All fixtures are hand-built from documented formats and marked "per spec, unverified against live API" (same convention as E2 InvestRight); live checks are `@pytest.mark.live`, skipped in CI.
- Follows the research 7-step slicing as slices **A..G** (A foundation, B ST-4.8 master, C ST-4.2/4.3 prices, D ST-4.5/4.1/4.4 fundamentals, E ST-4.6/4.9 macro + estimates, F ST-4.7 news, G ST-4.10 servers). Deviations, with reasons: (1) the shared MCP helper and the calendar are split out of "foundation" into their own steps so each step stays reviewable; (2) the security master is built **before** the schema for market data is consumed but its SQLite migration (0004) and the DuckDB migration (0002) both land in slice A so the schema/migration work is one explicit, reviewable unit for `sigma-migration-check`; (3) ST-4.9 estimates ride with the calendar-event table, so the "next results date" tool has data; (4) the servers are one slice with one step per server plus a registration step.
- **Every step ends with a full `make check` green** (not just a focused pytest). **No step commits or stages**; the orchestrator commits once.
- Ponytail: reuse `Adapter`, `make_client`, `cached_fetch`, `ReadOnlyServer`, `DataQualityError`/`parse_decimal`, `wrap_untrusted`, `get_secret`. No registries, no base class for one implementation, no `PriceProvider` hierarchy (an `Adapter` already is the interface; the US secondary is a second `Adapter` instance injected by config name).

Same data, ~60 lines, fixture-replayable. The endpoint is unofficial (ToS and breakage risk, see Risks).
   - `pandas`/`numpy`: not needed; models are frozen pydantic rows and `Decimal` (PID's `DataFrame | Model` is satisfied by the model branch).
   - `feedparser`: RSS 2.0 and Atom parsed with `xml.etree.ElementTree` + `email.utils.parsedate_to_datetime`. Hardening: payloads containing `<!DOCTYPE` or `<!ENTITY` are rejected before parsing (entity-expansion defence), with `# noqa: S314` justified in a comment.

6. **Identity and the `SecurityResolver` extension (BR-3, BR-4, BR-5, TD-1)**. The `SecurityResolver` Protocol and `Resolved` stay byte-compatible (`resolve(isin) -> Resolved | None`), so all seven call sites (`cas.py`, `cas_ingest.py`, `investright_normalise.py`, `csv_import.py`, `nivesh_cli/holdings.py`, `nivesh_mcp/holdings.py`) are untouched. Extension in two places:
   - `TableResolver.resolve` gains one fallback: no exact unresolved=0 ISIN row -> look up `security_alias(kind='isin', value=isin)` and return the current security (renamed/merged ISIN now benefits holdings ingestion for free). Existing tests keep passing; new test added.
   - New `SecurityMaster(conn)` in `nivesh_core/security_master.py` (composes `TableResolver`; satisfies the Protocol structurally) adds `lookup(query, market=None) -> Lookup(security_id | None, matched_by, candidates)`, `by_symbol`, `get(security_id)`, `cik_of(security_id)`. Resolution order: ISIN (exact, then alias) -> symbol (case-insensitive, exact, then alias) -> fuzzy name. Fuzzy: lowercase, strip punctuation and company suffix words (`ltd`, `limited`, `inc`, `corp`, `corporation`, `plc`), SQL `LIKE` prefilter on `name_norm` by query tokens (cap 300 rows), `difflib.SequenceMatcher` score; a single `security_id` is returned only when top score >= 0.92 and the gap to the second is >= 0.05, otherwise the ranked top 5 candidates. Because BR-5's call sites read the same `security` table the master fills, no re-wiring is needed; BR-5 is resolved by this design.
   - Row identity: one canonical `security` row per ISIN (exchange preference NSE > BSE); the other listing's symbol and the BSE scrip code become aliases. US rows: `market='US'`, `currency='USD'`, exchange from the SEC exchange field, `cik` alias. MF rows follow E2's existing convention (`symbol=<ISIN>, exchange='AMFI', amfi_code` set). Indices: `asset_class='index'`, no ISIN, from a fixed default list in code.
   - **Placeholder upgrade** (verified: `0001_core.sql` has `UNIQUE(symbol, exchange)`; `0003_holdings.sql` has `txn_dedup`; nothing references `txn.id`). For ISIN X with a placeholder P (`symbol=X, exchange='ISIN', unresolved=1`) and the master's canonical (symbol S, exchange E):
     1. No row holds (S, E): `UPDATE` P in place (same `security_id`, nothing repointed).
     2. A different real row R holds (S, E) and R.isin is NULL or X: merge P into R (step 4).
     3. R holds (S, E) with a **different non-null ISIN** (symbol reuse): conflict. P is left untouched, counted in `BuildSummary.conflicts` and printed with both ISINs; never fatal, never guessed.
     4. Merge, single transaction: `UPDATE OR IGNORE` repoints `holding_snapshot` and `txn` to R; rows left behind because they collide on a unique index (`txn_dedup`, snapshot keys) duplicate rows already on R, but each is **first copied as JSON into `master_merge_log`** (same transaction), counted in `BuildSummary.rows_dropped`, then deleted; then P is deleted. Any error rolls back everything including the log rows.
   - **Two real rows for one ISIN** (E2 can already hold an NSE and a BSE row): out of scope for merging; the master never touches existing real rows. `SecurityMaster.lookup` by ISIN with more than one resolved row returns ranked candidates (NSE first) instead of a single id; `TableResolver.resolve` keeps its existing `ORDER BY id LIMIT 1` (documented, unchanged). "One canonical row per ISIN" applies to rows the builder creates. Test: `test_two_real_rows_one_isin_lookup_returns_candidates_and_resolver_unchanged`.
   - Rename detection: a build that sees a known ISIN with a different symbol records the old symbol as an alias. Owner-maintained `config/security_renames.yaml` (`[{old_isin, new_isin}]`, may be empty) supplies merged/renamed ISINs.
7. **Prices (ST-4.2/4.3)**: India primary = NSE UDiFF bhavcopy zip (`BhavCopy_NSE_CM_0_0_0_<YYYYMMDD>_F_0000.csv.zip`) and BSE bhavcopy CSV, indices from NSE `ind_close_all_<DDMMYYYY>.csv` (includes India VIX), fallback and cross-check = Yahoo chart JSON (`.NS`/`.BO`); US primary = Yahoo chart JSON, configurable second = Stooq daily CSV. Bars are stored per source. Cross-check compares each primary bar's **split/bonus-adjusted close** with the secondary's close on the same date (Yahoo `close` is split-adjusted, bhavcopy is raw, so comparing raw would false-flag every split window; dividends are excluded from the comparison) and sets `flag = 'mismatch'` when they differ by more than 1 percent, `'single_source'` when no second bar exists. `adj_close` is computed from raw close and `corp_action` rows: split `ratio = new/old`, bonus `a:b` factor `b/(a+b)`, cash dividend factor `(prev_close - amount)/prev_close` on the session before ex-date; factors are cumulative backwards; all `Decimal`. India corporate actions come from the NSE corporate-actions JSON, US from Yahoo chart `events`. Symbols not in the master are skipped and counted in the ingest report (never auto-created).
8. **Fundamentals (ST-4.1/4.4/4.5)**: ADR-0005 (step D3) records the **provisional** desk-comparison choice (free-first): primary = exchange XBRL financial-results filings (NSE/BSE; regulator source, native `filed_at` so point-in-time is exact, free, no redistribution restriction on facts); fallback = Tapetide MCP (availability, coverage and licence unverified) behind the same standardised-row boundary; screener-style scraping rejected as primary on licence/ToS grounds; paid trial last resort. The ADR states in its first paragraph that the choice is provisional pending the deferred 30-company sampling (D1). The adapter output boundary is `StatementRow(period_end, period_type, item, value, currency, filed_at)` and `ShareholdingRow`; only the XBRL mapper is implemented. Standard item names (also the MCP vocabulary): `revenue, operating_income, net_income, eps, cfo, capex, total_debt, total_equity, shares_out`, bank/NBFC `gnpa_pct, nnpa_pct, nim_pct, casa_pct, car_pct`. EDGAR facts become quarterly values by `engine.statements.quarterise` (10-Q cash-flow and income facts are year-to-date: discrete quarter = YTD minus prior YTD; Q4 = FY minus 9-month YTD; instant items use `end`); derived Q4 rows carry the 10-K `filed_at`.
9. **Redaction-safe payloads (BR-15, plan 5 decision 3 extended)**: `redact_json` masks keys containing `token|secret|password|folio|aadhaar|apikey|authorization|cookie` or a `_`-part in `{pan, account, acct, key, email, phone, mobile, address, dp, client}` and any **string** with a 9-18 digit run. Rules for all E4 payloads: numbers are JSON numbers (Decimal to float at the MCP boundary; volumes and market values are ints, which redaction leaves alone); field names used: `security_id, symbol, exchange, isin, date, open, high, low, close, volume, adj_close, source, flag, ex_date, kind, ratio, amount, period_end, period_type, item, value, currency, filed_at, series_id, metric, period, revision_30d, revision_90d, available, reason, title_ref, text, event_type, materiality, sentiment, event_date, filing_id, form, section, citation, next_cursor, next_offset, total, candidates, score, matched_by`. Never: `key*`, `client*`, `account*`, `*token*`, `address*`. **EDGAR identifiers are never emitted as strings**: a 10-digit zero-padded CIK or an accession number (`0001193125-24-012345`, URL form 18 digits) would be masked, so tools return the local integer `filing_id`, `form`, `filed_at` and a `citation` string (`"<ticker> <form> filed <date> (filing <id>)"`); the full URL stays in the `filing` table for the report writer. News `url` is returned as stored (a masked long article id is a known, documented loss, see Risks). A test pushes a full payload from each server through the real wrapper and asserts numbers and names survive.

12. **Concurrency of stores for MCP (shared code: `init_stores`)**. Verified: DuckDB allows one read-write process **or** many read-only processes, never both; today `init_stores` opens DuckDB read-write on every call (`nivesh_mcp/holdings.py::_db`, three sites in `nivesh_cli/main.py`, three in `nivesh_cli/holdings.py`), so an in-flight market read would break every `holdings` tool, and a running `nivesh market ...` ingest would too. Fix, in one place:
    - `init_stores(data_dir)` keeps its signature. SQLite handling is unchanged. For DuckDB, if the file exists it first opens it `read_only=True`, reads `current_version`, and **returns without a read-write open when `have == migrate.latest_version(duck dir)`**. Lower version or absent file: today's read-write `apply`. `have > latest`: read-write path still runs `apply`, which raises the existing "newer than this code" `MigrationError` (downgrade refusal preserved). If the read-only probe hits DuckDB's lock error, a writer is active and (every writer enters through `init_stores`) the file is already current: skip DuckDB. Other probe errors propagate.
    - `open_duck(path, *, read_only=False)` gains the flag (default unchanged).
    - `nivesh_mcp/common.py::market_ctx()` runs `init_stores` **once per process per data dir** (module-level set), so a pending upgrade is applied once at first use/server start, then opens DuckDB `read_only=True` per call. A lock error at that upgrade or on any read becomes a clear "ingest in progress, retry" tool error.
    - `holdings.py` is untouched; its `_db()` now takes no DuckDB write lock when stores are current.
    - Contract check (`sigma-contract-check`): semantic widening only (fewer lock acquisitions), same signature and postcondition (both stores at latest). Existing callers are covered by their existing tests plus the new tests in step A1.

17. **Cache payloads are JSON-native; `cached_fetch` gains a `redact` flag (shared code)**. Broker/user data keeps the default. Secrets stay out by construction (vendor keys travel as request params outside the cached `params` and payload; asserted in the adapter tests).
    - **Contract check**: additive keyword with a default, no signature break; existing tests pass unchanged.
    - **Tests with real-sized payloads** (decision 14's <= 8 digit fixtures cannot catch this): `tests/adapters/test_cache.py::test_market_payload_survives_cache_hit_twice` (12-digit value string, URL with an 18-digit accession folder, 10-digit CIK, a nested `key`-named field; call twice inside the TTL, assert first result, cached result and the stored row are equal and unmasked) and `::test_default_redact_true_still_masks_digit_runs_and_key_fields` (existing behaviour). Payloads are built by concatenation in `tests/market_fx.py`, in-process only, never under `tests/fixtures`. ## Risks / post-ship notes
- Every wire format is spec-inferred and unverified (D2/D3): bhavcopy columns, Yahoo chart, EDGAR, Ind-AS XBRL tags, FRED series ids, FII/DII JSON, announcement feeds. A wrong guess fails loudly (`DataQualityError`/`SourceUnavailable`), not silently, but nothing is proven against live data.
- Yahoo chart is an unofficial endpoint (ToS gray area, can change or throttle without notice) used instead of `yfinance`; it is a fallback and cross-check for India but the **only primary for US prices**. Stooq is the second source; US price quality is therefore only as good as these two free feeds.
- The India fundamentals choice in ADR-0005 is provisional until D1 sampling; a different winner changes only `fundamentals_in.py`'s mapper, not tables or tools.
- NSE holidays come from owner-maintained config; the shipped sample is incomplete by design (fixed-date holidays only). Until completed, `last_trading_day` and gap detection can treat an NSE festival day as a session (false gap flags, never a missed real gap). A year absent from config raises loudly.
- NYSE close is approximated as 02:30 IST of the next date year-round (an hour off during US daylight time); acceptable for "last completed session", noted in the tool docstring.
- Redaction: field-name masking and the 9-18 digit string sweep are blunt. EDGAR CIK/accession strings and long numeric news-URL ids cannot survive as strings, so tools expose `filing_id`/`citation` and the report writer reads URLs from the store (D9). Any new payload field containing `key`, `client`, `account`, `token` is masked; guarded by a survival test per server.
- DuckDB single-writer: an ingest run blocks MCP market reads for its duration (clear error); `holdings` and other `init_stores` callers are no longer blocked (decision 12), but the probe assumes any lock holder came through `init_stores`; a foreign process holding the file read-write that is on an older schema is not detected until it exits. If agents run during nightly ingest this will bite; mitigations are scheduling (E11) or a WAL-style snapshot copy, not done here.
- difflib fuzzy matching is O(candidates) with a 300-row prefilter; very short or very generic queries ("bank") produce wide ranked lists, never a guess. If measured slow on a 50k-row master, swap to `rapidfuzz` (already in the lock).
- `quarterise` relies on EDGAR duration/`fp` conventions (YTD cash-flow facts, no explicit Q4). Companies with 52/53-week years or changed fiscal year-ends can mis-assign periods; the engine skips periods it cannot classify and lists them in the ingest report rather than guessing.
- Coverage gate now binds ~18 new modules of parsers; each step carries its own >= 90 percent target so the 85 percent gate has margin. If a step trips the gate, add tests, never lower the gate.
- The 20-tool surface adds token cost to every agent session that enables all servers; `.claude/settings.json` lists tools explicitly so a role can enable a subset (E7 concern).
- Master build assumes NSE-over-BSE exchange preference; a security delisted from NSE but live on BSE keeps its NSE row until the next build changes the canonical listing (aliases keep lookups working).

- `cached_fetch(redact=False)` for market data stores unmasked identifiers (CIK, accession) in the owner-only DuckDB cache; acceptable because the data is public and never PII, and the flag defaults to the old masking so no existing caller changes. A future adapter that handles user data must not pass `redact=False`.
- Placeholder merge drops duplicate `txn`/snapshot rows after logging them in `master_merge_log`; the log is the only recovery path (restore from `nivesh backup` otherwise). Symbol-reuse conflicts are reported, not resolved.
- PR text must state: the `yfinance` AC2 clause is satisfied by a direct Yahoo chart JSON call over `httpx` (decision 1), an unofficial endpoint with ToS and breakage risk (see above).
