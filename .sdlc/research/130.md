## Risks and gotchas
- **Token hygiene**: never write a token value anywhere. Reuse `tx.token()`/`tx.scheme()` (concatenated). For #4 use prose only, e.g. vendor text `"Error: Not found (tapetide-api): token not found"` as a string literal; do not assign literals to identifiers named token/secret/password/key, do not write the scheme word followed by a value in docs/comments. New dummy values by concatenation or neutral names (`bad`, `echo`).
- Behaviour pin: changing `_check_pledge` flips the existing `pledge_string_pct` hostile case; leave `pledge_huge_pct`, `pledge_over_100`, `pledge_negative`, `pledge_scalar` failing (acceptance says text only). Decision for planner: numeric NaN/inf pledge now also becomes None (via `_dec`), say so in the test name.
- `status: "none"` + text pct yields 0 (see gotcha above); acceptable per `_latest_pledge` docstring but the test must avoid it.
- Regex scoping (#4) has an unrecorded wording risk for shareholding; mitigated because the fallback is the same exception type with the vendor text.
- No live Tapetide call is needed or allowed: every fix and test runs on recorded fixtures (6 billed calls per company would be real money).
- Merge friction: #131 builds a provider registry and quota ledger on this same file; keep edits to the five one-line sites plus tests, no structural change.
