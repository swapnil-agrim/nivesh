# Research: E9 Idea generation (ST-9.1 to ST-9.5)
**Goal**: swapnil-agrim/nivesh#12 · **Lane**: large (recommend 4 ordered slices; live constituent fetch, R2 alert and ledger reads deferred) · **Date**: 2026-10-11

## Goal in one paragraph
Give the owner a few well-argued buy ideas per run instead of a ticker list. ST-9.1: investable universes from config (India: Nifty 500 + optional Smallcap 250; US: S&P 500 + Nasdaq-100 + optional Russell 1000) with a liquidity floor (20-day ADV >= INR 5 crore / USD 20M) and profile exclusions (sectors, names) removed; the screener consumes the universe instead of an explicit id list (absorbs #71 universe part) and a market-cap source feeds buckets (the #72 part ST-9.x needs). ST-9.2: four YAML presets (`lt-quality-value`, `lt-quality-growth`, `pos-pullback-uptrend`, `pos-breakout`) that run through the screener, plus a lint test that no rule uses trailing return as a standalone pass criterion (BR-12). ST-9.3: matches ranked by composite, max 2 per sector, existing holdings excluded or labelled ADD, shortlist size 8 (config). ST-9.4: `/ideas [india|us|both] [n] [preset]` runs the committee on the shortlist only, ranks by conviction then composite, reports the top n (default 5) BUY/ACCUMULATE ideas (thesis, entry zone, invalidation, weight, what-would-prove-wrong), says so when fewer than n qualify, writes every idea to the ledger (ST-12.1). ST-9.5: `/watch add TICKER [low high]` and `/watch` (distance to entry zone + latest verdict). Sources: PID ST-9.1..9.5 (lines 1205-1248), ST-4.8 (864), ST-6.8/6.9 (1029-1045), ST-7.9 (1123), ST-12.1 (1400), FR-30 (250), J-7 (166), sec 15.5 (526-533); acceptance `.sdlc/acceptance/12.md`; design `.sdlc/design/1.md` (row 78: E9 is 5 stories). Checked against worktree `.sdlc/work/12` (HEAD 2377d18 = E1..E8 merged, E8 via #89). Constraints: package `nivesh`; claude-agent-sdk pinned and faked in unit tests (no real model call, network, PII, secrets); deterministic engines in Decimal (no float/random/clock in `nivesh_engine`, enforced by a regex scan); no order/write tools for agents; the commit secret-scanner refuses credential-looking identifiers/literals (e.g. a variable named `secret`) even in tests/docs/config.

## Data-source findings (constituents, ADV, market cap)
- **Constituents**: no free, stable, keyless wire format is verified (existing master sources are "per spec, unverified against live", ADR-0005 style). Recommended deliverable now: an `index_member(index_id, security_id, as_of)` table (SQLite migration `0007`), a parser per source shape (NSE index constituent CSV: Symbol/ISIN columns; US: a CSV of ticker lists) and a `nivesh universe load --index NIFTY500 --file PATH` path that ingests an owner-supplied file (offline, like `import-csv`). Live URL fetching goes behind the existing `Adapter` + recorder seam but is deferred (unverified formats, rate limits, ToS). Membership resolves to `security_id` through `SecurityMaster` (ISIN first, symbol alias second), unresolved rows reported not dropped silently.
- **ADV**: extract the INR value-traded computation from `risk._days_to_trade` into one engine function `adv_value(bars, days, inr_per_unit)` (Decimal) used by both risk and the universe filter, so floors and days-to-trade agree. USD floor compares in USD (bar currency) before FX; INR floor in INR (crore = 10^7), config `universe.liquidity: {IN: {min_adv_crore: 5}, US: {min_adv_usd_m: 20}}`. Fewer than 20 bars with volume = excluded with reason "insufficient liquidity data" (never guessed).
- **Market cap**: reuse the existing close x `shares_out` path; add a registry metric `market_cap` (+ a bucket via `analysis.xray.market_cap` bands) so presets can require cap and the shortlist can label it. A true external source (#72: exchange/EDGAR/FMP market-cap) is deferred; the screener marks `market_cap` unavailable with the reason `no shares_out filed` (existing behaviour), consistent with the "no silent zero" rule.

## Risks
1. **No ledger** (largest dependency gap). AC and ST-9.4 require every idea in the ledger; ST-12.1 is unbuilt and owned by E12. Mitigation: build only the append-only table + insert/read API with triggers rejecting UPDATE/DELETE and a corrections-as-new-rows column (`corrects_id`); E12 later adds scoring and reads. Risk of conflicting schema with E12: keep the row shape exactly the ST-12.1 field list and note it in the ADR.
2. **Constituent data** cannot be fetched or verified offline; shipping a live fetcher would be untestable guesses. Mitigation: owner-supplied file import now, adapter later; universe emptiness is an explicit error ("no members loaded for NIFTY500; run `nivesh universe load`"), never a silent fallback to "all stored bars" (that would quietly widen the universe).
3. **Cost**: `/ideas` runs the `deep` committee on up to 8 names; with `both`, 8 per market. Cost gate (`gate`, `monthly_cost_cap`) can downgrade deep to quick; tests must use the fake SDK and assert tier passed. Add a hard cap on shortlist size (config max) so a bad config cannot fan out.
4. **BR-12 / BUY discipline**: presets must not make trailing return a standalone criterion (lint test over preset YAML: any rule on `roc_*`/`rs_*`/`price_vs_*` must co-occur with a fundamentals rule from the `fa`/`valuation`/`estimates` bundles). Final BUY is still governed by `committee_rules` (cap, veto); `/ideas` filters on the verdict, it never overrides it.
5. **Universe-relative metrics** (`rs_percentile`, score percentiles) change when the universe changes; goldens in `test_screen.py`, `test_scoring.py` must not silently shift (keep explicit-id path identical).
6. **Pinned-test edits**: engine scan list (`ENGINE`), coverage 85% gate over new engine/adapter/agent code, write-word scans (BR-16), migration tests. Plan the test files with the modules.
7. **Secret-scanner**: avoid identifiers/literals that look like credentials (`secret`, `token`, `key=`), including in fixtures (index "key" columns) and docs.
8. **Staleness / honesty**: stale bars or missing ADV must not pass the floor; membership `as_of` older than a configured max age (default 35 days, "refreshed monthly") should print a warning, not fail.
9. **Sector-cap ties and missing sectors**: securities with no `sector` need a deterministic bucket (`unclassified`, capped like any other) and a deterministic tiebreak (composite desc, then symbol).

## Recommended slicing and lane
**Lane: large.** Five stories, one new migration, three new engine/adapters modules, two new CLI commands, a minimal ledger and an ADR; the committee and screener reuse keeps each slice small. Suggested ordered slices (each independently verifiable, `make check` green at every step):
1. **ST-9.1 universe** (+ #71 universe part + market-cap metric): migration `0007` (`index_member`), `universe` config, constituent parsers + owner-file load command (`nivesh universe load|show`), `adv_value` extraction, exclusion helper with sector match, `universe` resolver replacing `universe_ids` default, `market_cap` metric. Tests: fixtures + `seed_universe`, boundary tests on the floor (exactly 5 crore, USD 20M), exclusions by sector and name, unresolved members reported.
2. **ST-9.2 presets + ST-9.3 shortlist**: `config/screens/*.yaml` (four presets, pure YAML), `nivesh screen --preset`, preset lint test, `shortlist` engine (composite rank, 2 per sector, ADD labelling by held ids, size 8). Property-style tests for the sector cap and tie-breaks.
3. **ST-9.4 `/ideas`** + minimal ledger: ledger core with append-only triggers; `nivesh ideas [india|us|both] [n] [preset]` as a `metered_run` (`deep`), scores shortlist once, `prepare_inputs` + `run_committee`, rank by conviction then composite (conviction order from `Confidence`), filter BUY/ACCUMULATE, "only k of n qualified" line, plain text and `--json`, ledger rows for every idea (all verdicts or only reported ones? write all committee verdicts on the shortlist: AC says "every idea"; reported ideas flagged). Fake-SDK tests only.
4. **ST-9.5 watchlist**: `watch` table, `nivesh watch add TICKER [low high]` / `nivesh watch` (distance to zone from last close, latest verdict from the ledger or last committee output), ADR-0011, README roadmap, pinned-test updates.
