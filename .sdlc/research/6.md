This is a new source of truth (DuckDB market tables, security master) plus 5 new servers, so it is large and must be split into ordered plan steps.

## Constraints & unknowns
- Unverified: the shapes of live NSE/BSE bhavcopy, yfinance, EDGAR companyfacts, FRED, RBI feeds. No network in research or tests, so fixtures are hand-written from documented formats and marked "per spec, unverified against live API" (same convention as E2 InvestRight). A live check belongs in a `live`-marked test (excluded by default per pyproject markers).
- Unverified: Tapetide MCP availability, coverage and licence; screener-style licence terms; BSE XBRL access. ST-4.1 can only be a desk comparison.
- Blocking: none. Two decisions need a call but have safe defaults (below).
- Non-blocking, R-1: dependency policy. pandas/numpy/yfinance/feedparser/exchange_calendars are heavy; PID rules say the adapter returns `DataFrame | Model`. Default recommendation: Pydantic models and stdlib (csv, zipfile, xml, `email.utils` for RSS dates) everywhere; add `yfinance` only if its fallback is implemented, and hand-roll a small NSE/NYSE holiday table (config/yaml, with weekday rule) instead of `exchange_calendars` unless the owner wants the pandas stack. Needs owner sign-off because it changes dependencies and `uv.lock`.
- Non-blocking, R-2: PID says US prices via OpenBB; OpenBB is a huge dependency. Recommend a `PriceProvider` interface with yfinance (or a direct Yahoo chart HTTP endpoint via httpx) as first impl; OpenBB deferred.
- Non-blocking, R-3: ST-4.7 classifier is a small-tier model; tests must use a fake classifier behind a Protocol. The real model-backed classifier goes via claude-agent-sdk and the cost meter; recommend shipping only a rule-based default plus the Protocol, deferring the LLM implementation.
- Non-blocking, R-4: ST-4.9 US vendor (FMP/Intrinio) needs a paid or keyed account; ship the adapter interface, a fixture-tested FMP-shaped adapter reading its key by `ref:` name, and the "unavailable" path for India.
- Non-blocking, R-5: secret-scanner lesson. The commit hook refuses credential-looking literals even in tests, docs and config. Any dummy API key, token or contact string (FRED key, FMP key, EDGAR contact) must be built by string concatenation (see the "two-step construction" note at `nivesh_adapters/investright.py:48`); config uses `ref:NAME` only. Fixtures redacted by the recorder already pass this; hand-written fixtures must not embed key-like params.
- Non-blocking, R-6: PII. The EDGAR User-Agent needs a contact email; the owner's email is PII, so config holds it as `ref:` or env, and tests use a concatenated `example.invalid` address.
- Non-blocking, R-7: DuckDB `INSERT OR REPLACE` into point-in-time tables loses restatement history; fundamentals PK should include `filed_at` (append-only), with "latest as of date" queries.
- North-star: `absent` (north_star.py), so no early warning.
- Review skills flagged: `/sigma-migration-check` (BR-2, BR-3 schema changes and the placeholder-to-real merge in TD-1) and `/sigma-contract-check` (resolver Protocol, five MCP tool contracts, Ttls/config schema). `/sigma-security-review` for EDGAR User-Agent/PII handling and untrusted text exposure (BR-16).

## Recommended slicing (ordered plan steps)
1. Foundation: config (Ttls keys, market settings), DuckDB `0002_market.sql`, shared MCP pagination/size-cap helper, trading calendar module (NSE holiday list in config/data file, NYSE likewise, `last_trading_day`, gap detection). Unblocks everything.
2. ST-4.8 security master (SQLite 0004, builder from fixture masters, resolver with ISIN/symbol/fuzzy/ranked candidates, rename/merge aliases, wraps TableResolver, placeholder upgrade). Early because every later adapter and server joins on `security_id`. Fuzzy via `rapidfuzz` (promote to direct dep) or `difflib` (stdlib; recommended by the ladder).
3. ST-4.2 + ST-4.3 prices (bhavcopy parser from fixture zip/csv, yfinance-shaped fallback via httpx fixtures, US provider, split/bonus/dividend adjustment, >1% cross-check flag, calendar-aware gaps). One step, shared adjustment code.
4. ST-4.5 EDGAR (CIK resolve, companyfacts to line items, filing sections, UA and rate limiter) then ST-4.1 ADR + ST-4.4 India fundamentals adapter (needs ADR decision; written to the chosen source with bank fields and pledge).
5. ST-4.6 macro/flows/FX (FRED, config series, `get_rates_snapshot`) and ST-4.9 estimates (US vendor adapter, India unavailable marker).
6. ST-4.7 news (RSS parse, URL + title-similarity dedupe, classifier Protocol with rule-based default, stored result, untrusted wrapping).
7. ST-4.10 five MCP servers, registry, `.mcp.json`, README, tests (tool names per PID 14.4, read-only, as_of/source, caps, IST calendar tools), then final `make check`.

Each step ends with `make check` green. The plan could also split steps 3-6 into separate PRs if the review size is a concern.

Large.
