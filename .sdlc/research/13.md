## Goal in one paragraph
Make every capability one command away and every output one consistent, dated, cited report. ST-10.1: a renderer producing Markdown and self-contained HTML (title, run time in IST, data as-of dates, 5-line summary, decision table, body sections, data gaps, sources, CR-4 footer), INR in lakh/crore (USD with INR equivalent), report + input snapshot + trace under `runs/<date>/<run_id>/`. ST-10.2: six templates (research note, portfolio review, fund doctor, ideas, brief, scorecard) with the PID sections, snapshot-tested from fixtures. ST-10.3/10.4: `/research TICKER [quick|deep]`, `/ta`, `/fa` (NSE:/US: prefix or ask on ambiguity), `/brief [india|us|both]` (<=400 words + one table) as prompt files plus handlers; absorbs #83/#84/#97 only where ST-10.x needs them. ST-10.5: `/status`, `/ingest`, `/scorecard` where dependencies exist. ST-10.6: citation validator (every numeric token matched to the run trace within rounding tolerance; unmatched listed; stamp `DRAFT - UNVERIFIED NUMBERS`; run status `needs_review`). ST-10.7: email/Telegram/Slack adapters (summary + decision table, HTML attached or linked, retry + log, PII scan, fixture-tested, nothing sent, secrets by reference). ST-10.8 (Could) only if cheap. Sources: PID ST-10.1..10.8 (lines 1250-1328), FR-31..33 (256-258), NFR-8/10/17 (279-288), CR-4 (310), J-3 (162), ST-2.8 (734), ST-7.9 (1123), ST-12.3 (1419), ST-13.3/13.4 (1486-1502); acceptance `.sdlc/acceptance/13.md`; design `.sdlc/design/1.md` (row 79: E10 = 8 stories). Checked against worktree `.sdlc/work/13` (HEAD 8d5e198 = E1..E9 merged, E9 via #99). Constraints: package `nivesh`; claude-agent-sdk 0.2.165 pinned and faked (no model/network/PII/secrets in tests); engines are Decimal-only (no float/random/clock; regex-scanned); agents get no write/order tools; the commit secret-scanner refuses credential-looking identifiers/literals even in tests/docs/config.

## 4. Risks, owner decisions (safest option chosen), design notes
**Owner decisions resolved (record as OD-n in ADR-0012; sign-off follow-up like #98):**
- OD-1 Run dir: `runs/<IST-date>/<run_id>/` as the AC says; legacy `runs/<id>` still readable. Safest: add `run_path(data_dir, run_id, run_dir_col)` that reads `run.run_dir` (set by `metered_run`), use it in replay/`review_flags`; new runs get the dated path; backup copies `runs/` wholesale (unchanged). If the owner prefers zero churn, keep `runs/<id>` and note the PID path is logical (not recommended: AC literal).
- OD-2 HTML: stdlib only (`html.escape`, one inline `<style>`, no JS/remote assets); NO jinja2/markdown dependency (a markdown parser would also render model prose as HTML = injection surface). Markdown and HTML are two serialisers of one `Report` model. Templates are Python builders, not template files, so `templates/` stays CSV-only and no `package-data` change is needed.
- OD-3 Slash commands are prompt files + CLI handlers. Interactive Claude Code has `Bash` denied (`settings.json`, pinned), so a `.md` cannot shell out. Files carry frontmatter `description`, `argument-hint`, `allowed-tools` (mcp__ names only); `/ta` and `/fa` can run natively with `mcp__engine__ta_compute/fa_compute`; committee commands (`research`, `ideas`, `brief`) document the contract and name the `nivesh <cmd>` handler. Do not touch `settings.json` allow/deny or the MCP registry. A new test pins: every file in `.claude/commands/` has frontmatter, only `mcp__` tools, a matching CLI handler, and no write verbs.
- OD-4 Delivery fails closed: scan subject, body and the HTML attachment with `scan_text`; any finding blocks that channel send (log kinds+positions only, never text); not a silent redact. Delivery is opt-in (empty config sends nothing).
- OD-5 Entry-zone numbers (model-proposed) are NOT exempt from the validator; they must match a level/price in the evidence (support/resistance/SMA/last close from `ta_compute`) within tolerance, else listed. Only code-produced numbers (clamped weight, coverage, dates, derived INR) are auto-registered. Expect some DRAFT stamps on first live runs; that is the intended honest outcome (OBJ-4).
- OD-6 `/brief` v1 is deterministic (no model call, zero cost); missing inputs print "unavailable (reason)".
- OD-7 #84 and `/review-funds` stay open; `/scorecard` command deferred (template only).

**Risks:**
- R1 Evidence in the trace is redacted: digit runs of 9-18 in string tool output become `[REDACTED]`, sensitive-looking keys masked. Validator must take its pool from three sources: trace `tool_result` outputs, `snapshot.json` `engine_outputs` (unredacted), and a `report_input.json` the renderer saves (the "input snapshot"). Present large amounts in lakh/crore so tokens stay small; treat `[REDACTED]` neighbours as "cannot verify" not "verified".
- R2 Run-dir refactor blast radius: ~14 pinned assertions on `runs/<id>` (see section 5). Do it in S1, one commit-sized change, with the resolver so old stores keep working.
- R3 Citation false positives: ordinals (`1.`), run id, dates in the header/footer, "top 5", `SMA200`, `FY26`, `Q3`, list numbers. Design (below) avoids by scanning typed blocks, not raw markdown.
- R4 Free-text model prose (bull/bear, theses) carries numbers the model computed itself (CAGR "about 18%"): will be flagged. Intended; do not widen tolerance to hide it (cap tolerance at the displayed-digit half unit, config-bounded).
- R5 Prompt injection into HTML: all model/news text goes through `html.escape` and control-char strip; no `href` from model text; tests with `<script>` and `javascript:` payloads. Delivery: Slack/Telegram markup injection (escape/plain text mode).
- R6 Cost/timing: `/research` deep and `/review-portfolio` fan-out go through `metered_run` (gate may refuse deep, `common.py:78-83`); NFR-10 is a nightly-bench concern, harness only here (live deferred, #77).
- R7 Secrets: a delivery config with fields named `*_token/*_key/*_secret` is legal only with `ref:` values (`config.py:192`), but the commit scanner flags credential-looking identifiers. Name fields `telegram_bot`, `slack_hook`, `smtp_login`, `smtp_credential` (values `ref:NAME`), recipients as refs too (an e-mail literal trips the PII scanner and is personal data). Tests build dummy values by concatenation and never name a variable `secret/token/key/password`.
- R8 Write-word scan (BR-16): `WRITE_VERBS` = place, modify, cancel, transfer, order, buy, sell, delete, withdraw (`nivesh_mcp/base.py:19-28`); applied to docstrings and names of scanned modules. Keep verdict labels (BUY/SELL, "order") in data, never in docstrings/names of new modules in a scanned list; avoid `place_*`, `transfer_*`, `delete_*`, `withdraw_*`. Put file/network writers (`save_report`, `deliver`) in `nivesh_adapters` + `nivesh_cli` and add the new files to a new `tests/safety/test_reports_safety.py` NEW list only after confirming names pass (pattern: `tests/safety/test_ideas_safety.py:15-24`).
- R9 Coverage gate: `--cov=nivesh_engine --cov=nivesh_adapters --cov=nivesh_agents --cov-fail-under=85` (`Makefile:3`); `nivesh_cli` is outside the gate. Keep logic in engine/adapters, handlers thin.
- R10 `needs_review` on `run.status` changes what `month_to_date` and `gate` see? No (`cost.py:35` sums by time only), but `tests/cli/test_metered_run.py:52` pins ok/error; add, do not change.

**Citation validator design** (`nivesh_engine/citations.py`, pure, Decimal):
- Input: `Report` blocks flagged `checked=True` (prose, decision-table cells, bullets) and an `Evidence` set. Structural text (title, headings, run id, run time, footer, list ordinals, template labels) is unchecked by construction. Extra guard: skip tokens glued to letters (`SMA200`, `Q3FY26`) and ordinals at line start.
- Token regex: optional sign, Indian or western grouping (`1,23,456.7`, `12,345`), decimals, optional unit suffix in {`%`, `x`, `lakh`, `crore`, `cr`, `k`, `m`, `bn`}, currency prefix `₹`/`$`/`INR`/`USD`. Parse to `Decimal`, record decimals shown `d` and a scale factor (percent 1/100 alternative, lakh 10^5, crore 10^7, k/m/bn).
- Evidence extraction: regex `-?\d+(?:\.\d+)?` over trace `tool_result` payload text (after `tool_json`-style block join), `snapshot.json` and `report_input.json`; also ISO dates `YYYY-MM-DD` as date tokens (report dates match ISO or `D Mon YYYY`/`Mon YYYY` forms rendered from them). Pool = `set[Decimal]` plus a sorted list for tolerance search (bisect).
- Match: token value v with `d` decimals matches evidence e if `|v - e*s| <= 0.5*10^-d (+ 1 unit of last place when derived by a documented rounding step)` for s in {1, 100 (fraction->percent), 1/100, 10^-5, 10^-7, 10^-3...} per the suffix; integers must match exactly or within 0.5. Rounding half-up vs half-even both covered by the half-unit window. Percent changes: also accept `(b/a - 1)*100` derived only if the renderer registered it (derived values come from the `Num` helper, never inferred by the validator, to avoid "everything matches something").
- Output: `Validation(unmatched=[(block_id, token, context)], checked=n)`; DRAFT stamp = fixed banner line first in MD and HTML, plus unmatched list section; `Metered.status = "needs_review"`; CLI prints the banner on stderr and exits 0 (a draft is not a failure).
- Tests (pure tables): grouping/lakh forms, rounding boundaries (12.35 vs 12.345), percent vs fraction, redacted-neighbour case, injected invented number flagged, structural numbers not flagged, empty evidence flags everything, property: renderer-registered values always match.

**Delivery design** (`nivesh_adapters/delivery.py`):
- `Message(subject, body_text, html, attachment_name)`; transports behind a tiny `Protocol` with `deliver(msg) -> None`; implementations: `EmailTransport` (stdlib `email.message.EmailMessage` + injected `smtplib.SMTP_SSL` factory, port/host from config, login via `SecretRef`), `TelegramTransport` (httpx `sendMessage` + `sendDocument`), `SlackTransport` (incoming-webhook POST; HTML linked as local path note or uploaded only if a file API is configured - default: summary + decision table text, "full report at <run dir>").
- Retry: `max_attempts` (default 3), injected `sleep` and backoff list, retry on 5xx/timeouts, not on 4xx; every failure logged to the run trace as an `error` record (message redacted, never the payload or URL secret), final failure returns a result object (does not raise, does not change run status).
- Message body = 5-line summary + decision table + CR-4 footer; it passes the same PII scan as the HTML attachment (OD-4).
- Fixture testing: `httpx.MockTransport` handlers and a fake SMTP class recording calls; assertions: nothing resolves DNS or opens a socket (monkeypatch `socket.socket` to raise in a fixture), payload contains no `ref:` resolution leak, URL/headers built from a resolved dummy ref are never traced or printed, retry counts and sleeps via the injected sleep, 4xx no retry, PII finding blocks send, empty config sends nothing. Config example block equals defaults and contains only `ref:` names.
- Config shape (new `delivery:` block, `extra="forbid"`): `channels: [email, telegram, slack]` default `[]`; per-channel refs (see R7); `max_attempts`, `timeout_s`. Resolve refs at send time only (like `metered_run`), error message names the ref, never the value.

**Other decisions:** reports save as `report.md`, `report.html`, `report_input.json` in the run dir with `write_private` (never overwrite; trace gets a `report_saved` record with digest via `tracer.saved`, `trace.py:117`; `KINDS` extended if via `RunStore`). `nivesh_core/timeutil.IST` + `to_iso` for the run time; INR/USD uses `settings.usd_inr` or the stored USDINR with its date (as E3 does) and states the rate and date in sources. CR-4 footer text is a constant checked verbatim by test, `Data as of <dates>` filled from the report's as-of set.
