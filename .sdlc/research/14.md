## 2. Proposed data model (migration `0008_scoring.sql`, forward-only, additive)
- `ALTER TABLE ledger_entry ADD COLUMN as_of TEXT` (run day), `price_date TEXT` (date of `last_close`), `source TEXT NOT NULL DEFAULT 'verdict'` (`verdict|holding_review`), `command TEXT` (copy of run command so a score row does not need joins; optional, can join instead). Existing rows: as_of falls back to `date(created_at)` IST; documented.
- `ledger_decision` (append-only, same two triggers): `id`, `entry_id` FK ledger_entry, `decision` CHECK in (`acted`,`skipped`,`partial`), `qty`, `price`, `currency`, `note`, `decided_at`, `corrects_id` self FK. Owner decisions are new rows, never edits (matches PID key rule). Latest row per entry wins in queries.
- `ledger_score` (append-only; one row per entry x horizon x scoring version): `entry_id`, `horizon_weeks` CHECK in (1,4,13,26,52), `status` (`scored|insufficient_data|pending`), `return`, `benchmark_return`, `cost_pct`, `excess`, `do_nothing_return` (SELL/TRIM), `hit` 0/1, `end_date`, `benchmark_symbol`, `basis` (note: `total_return_adjusted`, `price_index_fallback`), `scored_at`. UNIQUE(entry_id, horizon_weeks, status='scored') via partial unique index so re-runs are idempotent; INSUFFICIENT_DATA verdicts get a row with `status='insufficient_data'` so they are counted but excluded from hit rates.
- `paper_trade`/`paper_nav` only if slice 4 is built: trade (`entry_id`, `side`, `exec_date`, `qty`, `price`, `cost`), nav (`day`, `nav`, `benchmark_nav`).

## 5. Risks
1. PR size: 7 stories, ~3.6k lines of CLI+adapters already; this goal is large. Cut as below.
2. Look-ahead in scoring: horizon end must be <= latest stored bar; benchmark and security must share the same dates; use sessions not calendar days (`nivesh_engine/calendar.py`; NSE holiday list needs owner completion, see `config/nivesh.yaml`). Missing bars -> `pending`/INSUFFICIENT, never forward-fill silently.
3. Basis drift (split after issue) if scoring trusts stored `last_close`; mitigated by re-deriving from the current series (section 1).
4. TRI absent: scoring against a price index overstates excess; must label basis in every output.
5. Float / `random` in engines trip the regex safety scan; bootstrap must be integer-seeded.
6. Secret-scanner lesson: do not use identifiers or literals that look credential-like (avoid the words secret, token, password, key in code/tests/docs for the bootstrap "seed" use `rng_state`/`resample_seed` is fine; avoid "seed token"). Also avoid the word `order` as an MCP tool name part.
7. Triggers block updates: `ledger_score` rescoring must insert new rows (versioned) rather than update; partial-unique index design needed so idempotence is not via UPDATE.
8. Backfill: existing ledger rows have no `as_of`/`price_date`; fallback via `created_at` is IST date of write which may be after a weekend; document.
9. Coverage gate excludes `nivesh_core`/`nivesh_cli`; put logic in measured packages.
10. Golden baseline gate needs a stored baseline pass rate; first release has none (define: no baseline = report only, create baseline file in the PR).

## 7. Open questions with recommended defaults
1. HOLD and AVOID success definition? Default: HOLD scored (return/excess stored) but excluded from hit rate (hit = None); AVOID treated like SELL (hit if underperformed benchmark). Record in ADR.
2. Cost application? Default: subtract round-trip cost once from excess for BUY/ACCUMULATE; for SELL/TRIM "do nothing" comparison subtract nothing from the hold side and success = security return < benchmark return gross (as the PID states).
3. Horizon end when not a session? Default: last session on or before issue + 7*w days; pending until that bar exists.
4. Entry price for scoring? Default: close on issue `price_date` (consistent with ledger `last_close`), not next-day open (open fill is the paper portfolio only).
5. Benchmark TRI? Default: configured symbol; fall back to `analysis.ta.benchmarks` price index with explicit "price index" basis note; owner loads TRI later.
6. Calendar vs Indian FY for YTD turnover? Default: calendar year; configurable later.
7. Conviction monotonic strict? Default: non-strict (high >= medium >= low) with CI overlap reported, verdict text "monotonic / not monotonic / inconclusive".
8. Model training cutoffs for the look-ahead guard? Default: config map `evaluation.model_cutoffs` (model id -> date); unknown model or missing map => refuse in-sample, require eval start strictly after cutoff.
9. Baseline for the golden gate? Default: committed `tests/eval/baseline.json`; absent => report only; owner raises it at each release.
10. Record `/research` quick verdicts in the ledger? Default: yes only for deep/quick committee verdicts that already produce `CommitteeVerdict` and only if one call site; otherwise follow-up (ideas remains the sole writer plus holding review).
