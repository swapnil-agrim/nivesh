# Research: E3 US holdings ingestion (ST-3.1 to ST-3.4)
**Goal**: swapnil-agrim/nivesh#7 · **Lane**: large (low end; see rationale) · **Date**: 2026-10-10

## Goal in one paragraph
Bring US positions into the E2 holdings schema and consolidation without any trading capability: a US holdings CSV import (generic template plus Alpaca and Robinhood-export presets, symbol/quantity/avg cost in USD/lot dates, tickers resolved to NYSE/NASDAQ/ARCA + USD), a read-only US broker connector interface with an Alpaca read-endpoint preset (positions/account only, fixture-tested, no network) and an allow-list proxy over a broker MCP that bundles trade tools (covered by the tool-safety test), USD-to-INR conversion with rate and date reported plus INR/USD exposure %, and per-lot dates with USD and INR XIRR plus holding period. Source: PID sec 19 (lines 754-795, ST-3.1..3.4), 8.1 (line 202), NFR-1 (line 272), NFR-3 (line 274); design/1.md D-1 (line 51: CSV-first adapter behind the interface; Alpaca/Robinhood only as documented, fixture-tested presets, no network). It extends a schema that is hard-wired to INR (Holding has no currency; `upsert_security` writes `'INR'`), so it touches core model, store, migration, consolidation, MCP and the safety test. No new heavy dependency is needed.

## Decisions the plan must make (with recommendations)
- D-A Currency in the schema. Recommend: additive migration 0005: `holding_snapshot` gains `currency TEXT NOT NULL DEFAULT 'INR'` and `value_local TEXT` (native value; for INR rows equals value_inr). Keep US native amounts (USD `price`, `avg_cost`, `value_local`) authoritative; derive INR at read time in `nivesh_engine/fx.py` using the latest `usdinr` on-or-before the valuation date, so `value_inr` for a USD row is a snapshot-time value and is re-derived (and flagged) at consolidation. For a missing rate: either (a) refuse import with a clear "USDINR unavailable, run `nivesh market macro`" error, or (b) store a nullable INR (needs SQLite table rebuild of `holding_snapshot` since NOT NULL cannot be dropped; heavier). Recommend (a) for import plus read-time `unavailable` marker with value_inr=None in the consolidated/MCP output (Row.value_inr becomes `Decimal | None` only for USD rows, or add a parallel `fx` object). Never write 0 or the `usd_inr` config value.
- D-B Lots storage. Recommend a new `lot` table (id, ingest_id, account_id, security_id, acquired_on TEXT, quantity TEXT, cost_per_unit TEXT, currency) rather than overloading `txn`: `txn` is typed (purchase/redemption), its dedup index and `list_transactions` feed the MFs surface, and `Txn.amount` has no currency; mixing USD lots in would corrupt INR-assumed reads. If the lot table is judged too heavy, `txn` with `txn_type='buy'` plus a `currency` column is the fallback. Holding-level avg_cost then comes from lots (quantity-weighted) when lots are present.
- D-C XIRR scope (ST-3.4 depends on unbuilt ST-6.6). Recommend: implement a minimal, pure, Decimal-safe `xirr(cashflows)` in `nivesh_engine/returns.py` (Newton with bisection fallback, returns `None`/unavailable when no sign change or fewer than two flows), ~40 lines, full tests (known textbook vectors, single-lot, negative return, no-convergence). Rationale: the AC explicitly requires XIRR in USD and INR and ST-6.6 later can adopt or replace it behind the same signature; deferring would fail AC4's headline clause. INR XIRR needs FX per flow date: use the `usdinr` observation on-or-before each lot date, and the valuation-date rate for the terminal value; if any rate is missing, report INR XIRR as unavailable (USD XIRR still shown). Terminal value for XIRR needs a market price: CSV rows only have cost (book value), so use E4 `market_store.get_bars` last close for US tickers when stored; else XIRR is unavailable with reason "no price". This dependency on stored prices is the main hidden coupling. If this is judged too large, defer the INR-XIRR half and ship USD XIRR + holding period; record as follow-up.
- D-D New sources. Recommend `Source` gains `us_csv` and `alpaca` (precedence: investright > cas_demat > cas_rta > alpaca > us_csv > csv, or put alpaca above us_csv) so coverage reports label them. ACCOUNT_KIND maps both to `manual`/`broker`. MCP `get_holdings(source=...)` picks them up automatically via PRECEDENCE; update the error message test.
- D-E Broker proxy shape. Recommend `ReadOnlyProxy(upstream: ToolCaller, allow: frozenset[str])` exposing only names in `allow`; construction fails if any allowed name `is_write_name`; `call(name, args)` raises `RegistrationError`/`NiveshError` for non-allow-listed names; `list_tools()` filters. No network; tests drive a fake upstream that bundles `place_order`, `cancel_order`, `get_positions`, `get_account_info`. Not registered as a `ReadOnlyServer` unless an actual stdio proxy server is wanted; if it is, it must go in `registry.SERVERS`, `.mcp.json`, `.claude/settings.json` (see test_tool_safety.py:77-88 for the gates). Recommendation: ship the proxy as a library class plus tests this goal; defer the runnable stdio proxy server (no real broker MCP to wrap, Q-1 unanswered).
- D-F Robinhood. PID: "only if its read tools can be isolated". No Robinhood MCP or export spec is in the repo; ship a Robinhood-export CSV preset only (header mapping documented "as of writing, unverified against a real export", same convention as ADR-0004 D4) and defer any Robinhood connector.

## Redaction-safe field names (ADR-0004)
Use: `symbol`, `exchange`, `currency`, `quantity`, `avg_cost`, `price`, `value_usd`, `value_inr`, `fx_rate`, `fx_date`, `fx_source`, `acquired_on` (lot date), `holding_days`, `xirr_usd`, `xirr_inr`, `exposure_pct`, `source`, `source_label`, `as_of`. Avoid in outputs/fixtures/config: any key containing `token`, `secret`, `password`, `authorization`, `cookie`, `apikey`, or an underscore-part `account`, `acct`, `key`, `client`, `address`, `email`, `phone`, `pan`, `dp`. Alpaca's own fields `account_number`, `id`, `APCA-API-KEY-ID`/`APCA-API-SECRET-KEY` headers must be dropped or mapped at the adapter boundary (and never stored). Emit JSON numbers, not strings: strings of 9+ digits (large `market_value`, volumes) are masked by `redact.py:41`; string-typed Decimals in fixtures should stay under 9 digits or be converted. `source_label` stays letters/short hex (digit runs). Alpaca UUID `asset_id` contains digit runs possibly 9+ contiguous in hex? UUID groups are separated by hyphens (max 12 hex chars, can hold a 9+ digit run), so drop `asset_id` from outputs.

## Secret-scanner caveat
The commit hook refuses credential-looking literals even in tests, docs, config and fixtures (precedent: `investright.py:48` "Two-step construction avoids a secret-scanner false positive", `:62-63` builds `"api_" + "key"`; research/6.md R-5; CI also runs gitleaks, `.github/workflows/ci.yml:28-37`). For this goal:
- Build header names and dummy values by concatenation: `"APCA-API-" + "KEY-ID"`, `"APCA-API-" + "SECRET-KEY"`, dummy values like `"test-" + "alpaca-" + "id"`; never a literal 20+ char alphanumeric string, never `PK...`/`AK...` shaped Alpaca-style ids, never a base64 blob.
- Config uses `ref:NAME` only (e.g. `ref:ALPACA_KEY_ID`, `ref:ALPACA_SECRET`); the example base URL is `https://paper-api.alpaca.markets` (public) or `.invalid`.
- Hand-written Alpaca response fixtures must not embed key-looking strings; replace `account_number`/`id` fields with absent or short placeholders. Recorder-produced fixtures are redacted already, hand-written ones are not.
- Docs/ADR/runbook examples: describe the header names in prose with the split form; do not paste sample credentials.

## Risks
- R-1 Silent INR default: any path that falls back to `usd_inr`, rate 1, or zero for a missing rate violates AC3. Mitigate with tests that assert `unavailable` and `value_inr is None`.
- R-2 Currency leakage: INR-assuming code (`Row.value_inr` sums, `invested`, `pnl`, `cost_coverage`, the book-value note) will mix USD into INR totals if USD rows are not converted first. Needs a total-currency test.
- R-3 Consolidation duplicates for US tickers without ISIN when exchange labels differ across sources (TD-4).
- R-4 Safety discovery silently skipping a class not named `*Client`/`*Broker`/not an `Adapter` (TD-6).
- R-5 Redaction masking numeric strings or sensitive-looking keys in new payloads (BR-16); also masked output hides bugs in tests, so assert on actual values.
- R-6 Secret-scanner refusal at commit (caveat above) and gitleaks in CI.
- R-7 Scope creep from XIRR: terminal price needs stored US prices; keep it to a pure function plus a thin caller.
- R-8 Hard-coded `"INR"`/`NSE` defaults in E2 code paths that US imports might accidentally hit (csv_import `_holding` line 102; `convert_preset`).
- R-9 Re-running US import: CSV dedup uses file digest only (`ingest_digest`); lots in a new table need their own dedup so a re-import of an edited file does not double lots (lots are per-ingest, latest-view semantics must apply the same way as snapshots).
- R-10 Coverage gate: engine and adapters must stay at or above 85% with the new modules fully tested.
