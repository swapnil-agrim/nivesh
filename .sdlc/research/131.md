3. **`nivesh fa --cross-check` does not exist** (only `mf nav --cross-check`, `nivesh_cli/mf.py:88`). The issue's wording "fa --cross-check/ a new fundamentals compare" is a new surface either way.
4. **Tapetide's recorded payload has no minority-interest row** in any of the four sections (`quarterly`, `profit_loss`, `balance_sheet`, `cash_flow`) and the BSE tag map has no non-controlling tag (`fundamentals_in.py:33-50`). The only derivation is EPS x shares (= profit attributable to the parent), valid for the **latest fiscal year only** (shares_out is derived for the latest balance sheet only, `fundamentals_tapetide.py:465-480`; ADR-0015 D11/X1). Reproduced offline from the recorded fixtures: RELIANCE gap **+18.55%** (95,754 vs 80,772.5 crore), HDFCBANK **+4.22%** (79,219 vs 76,011.2; its face value is SYNTHETIC), ITC +1.60%, TCS +0.44%, INFY +0.30%.
5. **Reads ignore `source`.** `get_statement_rows` / `get_statement_rows_many` (`nivesh_core/market_store.py:267-295, 297-323`) select no source column; `latest_as_of` keeps the highest `filed_at` and breaks ties by arrival order (`nivesh_engine/statements.py:latest_as_of`). Today this is harmless (BSE rows are written only when Tapetide gave nothing, `market_ingest.py:456-481`). The moment two providers are enabled, duplicate (period, item) rows from different sources reach `fa`, valuation, `mf_report` and the MCP tools with nondeterministic tie-breaks. Field-level selection by priority needs a source-aware read. Precedent: price bars rank by `SOURCE_PRIORITY` (`market_store.py:16-29`).
6. **Single, exact chokepoint for the gate**: the only HTTP POST to Tapetide is `fundamentals_tapetide.py:196` (`self._client.post(URL, ...)` inside `_rpc_inner` `:182-223`), after `self._limiter.wait()` `:187`. Everything funnels through `_call` `:225` -> `_rpc` `:171` -> `_rpc_inner`. `self.calls` (`:152`, `:222`) counts successful calls only, so the ledger (every attempt) and `rep.tapetide_calls` will differ on failure paths by design.
7. **Atomic-claim precedent exists**: `claim_job` (`nivesh_core/alerts.py:42-78`) uses `BEGIN IMMEDIATE` on the SQLite connection, commits before returning, takes an injectable `now`. The ledger belongs in SQLite (ADR-0002: SQLite transactional, DuckDB analytical with a single-writer lock; the CLI's `stores()` already reports "market database in use" when DuckDB is locked, `nivesh_cli/market.py:78-85`), as migration `0010`.
8. **Two existing tests pin "last SQLite migration is 0009"** and will fail on any `0010`: `tests/core/test_ideas_migration.py:41` and `tests/safety/test_reports_safety.py:126-131` (named `test_no_new_migration_...`, an E10 guard). Both must be updated in the same slice.
9. **Upstox does publish a Company Fundamentals API** (income statement, balance sheet, cash flow, share holdings, corporate actions, company profile, key ratios, competitors), keyed on **ISIN**, units crore, no filing date, no pledge, no minority line seen (details in section 6). That makes the skeleton feasible, with every row's `filed_at` an estimate.
10. **`NotConfigured` does not exist** (`nivesh_core/errors.py` has `ConfigError`, `SecretNotFound`, `MarketDataError`, `RateLimited`, `SourceUnavailable`). Today a missing Tapetide token halts with `SourceUnavailable("TAPETIDE_TOKEN not set; ...")` (`fundamentals_tapetide.py:162-168`). Add `NotConfigured(MarketDataError)` or reuse `SourceUnavailable`; either keeps `Run.get`'s `except (NiveshError, httpx.HTTPError)` working (`market_ingest.py:117-142`).

## 3. Persistence, time, concurrency, priority
- **Stores**: SQLite `nivesh.sqlite` (WAL, autocommit `isolation_level=None`, `PRAGMA foreign_keys=ON`; `nivesh_core/db/sqlite.py`), DuckDB `nivesh.duckdb`. Migration tests: `tests/core/test_scheduler_migration.py` pattern (`fresh()` with `migrate.apply`, columns, triggers, `>= 9`, backup round-trip).
- **Pins to update with `0010`**: `tests/core/test_ideas_migration.py:41` and `tests/safety/test_reports_safety.py:130`. Others use `>=` or `latest_version` (`test_init.py:31`, `test_scheduler_migration.py:43`, `test_us_holdings_migration.py:43`) and survive.
- **Where the ledger lives**: new `nivesh_core/quota.py` (store module, like `alerts.py`, `watch.py`) taking a `sqlite3.Connection` and an injectable `now`; config in new `nivesh_core/fundamentals_config.py` wired into `Settings` (`config.py:304`) next to `ScoringSettings` etc. (module style: `scoring_config.py`).
- **Table sketch (recommendation)**: `vendor_call(id, vendor, called_at TEXT UTC ISO, day_ist TEXT, tool TEXT, symbol TEXT, priority TEXT, kind TEXT CHECK in (call, manual), outcome TEXT)` plus `vendor_limit(id, vendor, daily, monthly, set_at)` append-only, latest row wins. Counting: `day_ist = ist_date(now)`; month = first of the IST month (`substr(day_ist,1,7)`). Use `ist_date`, never `ZoneInfo` (none in the repo; `IST` is a fixed +05:30). 00:00 IST = 18:30 UTC the previous day. Keep timestamps ISO (`to_iso`): `tests/security/test_pii_e2e.py:213-225` scans a full SQLite dump with `scan_text`, whose `digits` pattern flags any 9-18 digit run (`redact.py:46`), so **no epoch-ms or compact `YYYYMMDDHHMMSS` columns**.
- **Atomicity**: `BEGIN IMMEDIATE` -> count daily and monthly -> check caps and priority floors -> `INSERT` -> `COMMIT` before the HTTP request; never refund. A crash between reserve and POST over-counts by one (safe). "Calls already made by a run count even if it later fails" holds by construction because the row is committed at reserve time (a `DataQualityError` abort, `Run.get` `:130-132`, cannot roll it back). sqlite3 default busy timeout is 5 s; two-connection test on a file DB is the concurrency test. Precedents: `alerts.py:42-78`, `ledger.py:118,303`.
- **Month boundary**: IST calendar month, 1st 00:00 IST, with a `month_start_day` knob (the vendor's billing anchor is UNVERIFIED).
- **Priority classes (holdings > watchlist > universe)**: `ingest_fundamentals` has only a `SecurityRow` and the `sql` connection (`market_ingest.py:484-492`), so class is derived: held = `latest_holdings(sql)` (`nivesh_core/holdings_store.py:246`, match on `isin`/symbol); watchlist = `watched(sql)` (`nivesh_core/watch.py:46`, `security_id`); universe = `members_of` (`nivesh_core/membership.py:108`) over `settings.universe.indices` (`universe_service.py:enabled_indices`). **No bulk fundamentals path exists today** (callers: `nivesh_cli/market.py:235` only), so classes only matter for single-symbol runs until a bulk caller appears; implement them as headroom floors in the gate and test them at ledger level.

## 6. Provider seam design inputs
**Fit to the existing classes.** The deliberate pattern is `Adapter._fetch` (network, JSON-native) -> `cached_fetch` -> pure mapper (cache hit and fresh fetch parse identically, `market_ingest.py:1-8`). Keep it: a provider = (cacheable `Adapter`s) + (pure mappers) + (an orchestrator method) + static metadata. Proposed minimal protocol in a new `nivesh_adapters/providers.py`:
- `Capability` enum: `statements, shareholding, pledge, actions, estimates, bank_metrics, news`.
- `ProviderInfo` (frozen): `id`, `sources` (stored source names, e.g. `tapetide`, `tapetide_est`), `capabilities`, `keyed_on` (`nse_symbol | bse_code | isin`), `credential` (secret name or None), `revenue_basis`, `profit_basis`, `filing_dates` (`declared | estimated | mixed`).
- `FundamentalsProvider` (ABC): `info`, `collect(ctx) -> ProviderResult(statements: list[StatementRow] by source, shareholding, notes, skipped, failed, calls)`, where `ctx` carries `sec`, `master` (for `bse_code` alias), `today`, and a `get(adapter, params, label)` callable (= `Run.get`; pass a callable, do not import `market_ingest` from the registry module: circular).
- Registry: dict `name -> factory(spec)` in `providers.py`; "one file plus registration" = one new module + one registry entry; tests parametrize over the registry so a new provider cannot skip the contract.
- Config block `fundamentals.providers`: ordered list of `{name, enabled, role: primary|fallback, plan: {daily, monthly, min_interval_s, month_start_day, reserve_pct}, credential: ref:NAME}`; defaults reproduce today's behaviour (tapetide primary enabled, bse_xbrl fallback enabled, upstox disabled). `role=fallback` preserves "BSE only when nothing arrived" and keeps single-provider behaviour unchanged.
- Safety-test constraints: `tests/safety/test_tool_safety.py:120-130,160-175` discovers every `Adapter` subclass in `nivesh_adapters/*` and requires no public method whose name contains a write verb (`place, modify, cancel, transfer, order, buy, sell, delete, withdraw`, `nivesh_mcp/base.py:19-29`); `MARKET_ADAPTERS` pins the current names (add Upstox's class name to it).

  1. *Ledger store*: SQLite `vendor_call` + append-only `vendor_limit`, migration 0010 (not DuckDB: single-writer lock, ADR-0002).
  2. *What counts as a call*: every request that reached the POST, committed before sending, never refunded; store `outcome`. Conservative while failed-call billing is unknown.
  3. *Gate position*: reserve inside `_rpc_inner` between `limiter.wait()` and `post`; `ingest_fundamentals` builds the budget from `(sql, settings)` and injects it (`budget=` kwarg); no-token and halted paths never reserve. Add a test that the CLI path always writes the ledger so the gate cannot be bypassed by a new construction site.
  4. *Cap breach behaviour*: raise a halting `RateLimited` subclass naming the window and reset time; `Run.get` records it, `_dedupe_tail` collapses repeats; `--refresh` goes through the same gate; warn at 80% of either window in `rep.notes` and `quota status`.
  5. *Month*: IST calendar month, `month_start_day` knob (default 1).
  6. *Priority*: derived class with headroom floors, `reserve_pct: {watchlist: 10, universe: 30}` of the daily cap kept free for higher classes; holdings may use 100%. Tuneable in config; tested at ledger level.
  7. *`quota set`*: appends a `vendor_limit` row that overrides config (latest wins; `status` shows the source); plus `--used-today N` writes a `kind=manual` entry because the quota is shared with other Tapetide clients and the vendor sends no remaining-quota header (ADR-0015:193). Owner may drop `--used-today`.
  8. *Provider roles*: `primary` providers all run (they cost quota); `fallback` only when no primary produced statements (keeps today's BSE behaviour and single-provider unchanged).
  9. *Field-level selection*: read-time, per (period_end, period_type, item) by provider priority, within a provider the latest `filed_at`; `StatementRow` unchanged; with one provider the selector is a no-op. `compare` reads per-source rows (0 calls), reports `% difference` against the priority provider with a configurable tolerance (suggest 1% statements, 0.5 pp shareholding), lists "only in X" items, never averages. `fa --cross-check` = thin pass-through that appends the compare block (read-only), or defer; recommend shipping `compare` first.
  10. *Attributable*: engine-derived, labelled, latest FY only, consolidated kept for CAGR/CFO ratios; DCF financial branch uses attributable, the FCF branch stays consolidated and labelled. Gap within 3% = "no minority detected" label; below -3% = unavailable with a reason.
  11. *Revenue basis*: provider-level label, no per-symbol table.
  12. *Unknown-symbol short-circuit*: stop after the first scoped not-found (saves 3 calls).
  13. *Upstox mapping scope*: income statement revenue/net_profit, balance sheet total assets/equity capital, cash flow operating, promoter percentage, corporate actions mapper (not wired); no pledge, no `public_pct`, all `filed_at` estimated and source-labelled `upstox` with the estimated-date flag; disabled by default; missing token or ISIN -> `NotConfigured` with the reason.
  14. *Follow-up wording (#136.3)*: do not invent vendor text; superset regex clearly labelled, ledger is the monthly guard.

## Risks
- Quota semantics unknown (failed-call billing, monthly anchor, Starter per-minute limit, header presence): conservative counting and a `month_start_day` knob; capture real wording only if observed.
- Attributable profit is approximate (weighted EPS vs period-end shares) and limited to one year; the issue text assumes more. Mitigated by labels and the 3% rule; owner scope confirmation requested.
- Multi-provider reads: without the source-aware selector, enabling a second provider silently double-counts or flips values; ship the selector in the same slice as any second enabled provider.
- Merge friction on `fundamentals_tapetide.py` and `market_ingest.py` across S0-S5 and with any parallel goal; keep hunks disjoint and sequence S0 first.
- Upstox shapes come from a summariser read of public pages: the skeleton is fixture-tested only and disabled; ADR must state UNVERIFIED for every format.
- Coverage gate 85% on adapters/engine: every new adapter/engine branch needs tests; `nivesh_core` code is outside the gate but should still be tested.
- PII/secret scanners: new fixtures, ADR, runbook and the SQLite dump must be scan-clean (no 9+ digit runs, no scheme word + value, no credential-shaped literals).
- Flaky `test_delivered_payloads_pass_scan_text` (#113) can fail `make check` alone; re-run.
- Gate bypass: the adapter can be constructed without a budget (tests, scripts). Mitigation: required in `ingest_fundamentals`, plus a test that the CLI path writes ledger rows equal to `tape.calls`.
