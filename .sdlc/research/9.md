**Goal**: swapnil-agrim/nivesh#9 · **Lane**: large (recommend 3 ordered slices plus a foundation step) · **Date**: 2026-10-10

## Goal in one paragraph
Compute, in deterministic Decimal-only code, every number the research committee will use: technical indicators with known-answer tests (ST-6.1), support/resistance levels, market regime and classified positional setups (ST-6.2), fundamental metrics with a point-in-time `as_of` and bank/NBFC variants (ST-6.3), valuation history vs own 5y/10y median and peers plus reverse-DCF and a base/bull/bear range (ST-6.4), a red-flag detector with hard/soft severity and evidence (ST-6.5), portfolio X-ray with allocation, drift, concentration, HHI, look-through and per-holding and total XIRR (ST-6.6), risk metrics (vol, drawdown, beta, correlation, days-to-trade, pro-forma weights) (ST-6.7), a YAML rule screener that skips and reports rules on missing data and runs 1,000 securities well under 60 s (ST-6.8), and a composite factor score with versioned horizon weights, a BR-12 property test and a hard-flag `cap=HOLD` (ST-6.9). It also folds in follow-ups #53 (XIRR bracket tops out, +100% in 30 days returns None; add an all-negative-flows test returning None with a reason) and #54 (`lots_cover_quantity` uses `>=`; make exact and add an over-covered state). Source: PID sec 22 (lines 962-1046), FR-18..FR-22 (233-237), sec 15.1/15.2/15.4/15.5/15.6 (480-545), BR-2/6/11/12, sec 13 data model (354-379), sec 14.4 (`nivesh-engine` tool list), acceptance `.sdlc/acceptance/9.md`, design `.sdlc/design/1.md` (row 7 "E6 depends on 4"). Checked against `.sdlc/work/9` (HEAD ff5f908 = E1+E13+E2+E4+E3+E5 merged; E5 shipped, so look-through ST-5.5 and FIFO lots exist). Constraints: package `nivesh`; no numpy/pandas/scipy/TA-Lib/hypothesis in `pyproject.toml:9-19,28-37`; Decimal only; no network; no PII; coverage gate 85% on `nivesh_engine` + `nivesh_adapters` (`Makefile:3`).

## Decisions the plan must make (with recommendations)
- D-A Statement vocabulary: define `FA_ITEMS` (names, units, which are bank-only) in `fa.py`; metric entries carry `inputs` and `available`. US concepts extended additively in `statements.CONCEPTS` (re-derive on `edgar_companyfacts.json`, bump fixtures); India items: no change in E6 (see Q-2). EBITDA = operating_income + D&A where both exist; never use India `operating_income` (PBT) as EBIT; ROCE for India needs total assets/current liabilities: unavailable until #39/#46.
- D-B Config: `analysis:` block in `nivesh.yaml` (pydantic `AnalysisSettings`, `extra="forbid"`, Decimal fields via validators like `MfSettings`), including `weights_version` string and weights per horizon summing to 100; no secret-like keys (scanner `_SECRETISH`). Do not introduce `methodology.yaml` (second config path, second loader, second schema); record in ADR that PID's file name is satisfied by this block.
- D-C Indicator conventions (ADR): SMA simple; EMA alpha 2/(N+1) seeded with the SMA of the first N closes (TA-Lib); RSI/ATR Wilder smoothing seeded with the SMA/mean of the first N changes/true ranges; MACD (12,26,9) with the signal EMA seeded by the SMA of the first 9 MACD values; ROC = close/close_n - 1 over 63/126/252 sessions; realised vol = sample std of log (or simple) daily returns x sqrt(252) (state which; reuse `mf_returns` definitions, which use simple returns: be consistent); Bollinger width = (upper - lower)/middle with population std, k=2; relative strength = ratio line and its change plus percentile rank in the supplied universe; weekly trend from resampled weekly closes (last close of the ISO week) with 10/40-week SMAs; 50-DMA slope = (SMA50_t - SMA50_{t-20}) / SMA50_{t-20}. Known answers: hand-derived tiny-series (e.g. 10 closes, window 3) asserted exactly, an independent straightforward reimplementation inside the test (float, loose) as a cross-check, and a published textbook RSI worked example (Wilder's classic 14-period sheet) only if reproducible by hand; every long-window null carries `reason="need 200 bars, have N"`. The 1e-6 tolerance is asserted against these.
- D-D Valuation: multiples from price at each historical `as_of` (month end) over annual statements filed by then (extend `stock_multiples`); P/E = price / EPS (TTM where 4 quarters exist, else last annual, labelled); percentile = share of historical observations <= current; median; peer median over `peers_of`, minimum peer count else "insufficient peers". Reverse DCF: solve implied growth g over N years (default 10, fade to terminal growth) so the DCF of FCF (or earnings for financials) at discount rate r equals market cap, by bisection on Decimal; fair-value range base/bull/bear = DCF on explicit (growth, discount, terminal) triples from config, all returned in the output (`assumptions`). Negative or missing FCF gives "not meaningful" with a reason, never zero.
- D-E Setups: rule table in ADR with thresholds in config. Proposed first cut: trend continuation (close > SMA50 > SMA200, SMA200 slope up, RSI 50-70, no breakout in the last 10 bars), pullback (uptrend as above, close within X ATR of SMA50/21EMA and RSI < 50 or below prior swing), breakout (close above resistance level with volume >= 1.5 x 20d avg), base (low ATR% range of N weeks, tight Bollinger width percentile, above/near SMA200), downtrend (close < SMA50 < SMA200), none. Entry zone = band around trigger; stop = entry_low - 2 x ATR (spec default); invalidation = nearest support below (or the stop if none); reward/risk = (nearest resistance or measured target - entry) / (entry - stop). One golden fixture per type plus ambiguous-priority fixture (precedence order fixed and documented).
- D-F X-ray rows: `Row` has no sector; join by ISIN/symbol through `SecurityMaster` into a `SectorOf` mapping passed in. Market cap: bucket only when shares and price exist; others "unclassified" with weight reported. Drift per class = actual% - target%; `positions over limits` from `Profile.max_position_pct` and `max_sector_pct`; HHI = sum(w^2) over INR-valued rows, effective N = 1/HHI; weights exclude rows with unavailable INR value and report them (house rule from `consolidate.py:13-15`).
- D-G XIRR scope: per holding where dated flows exist (US `Lot`, MF `Txn` via `mf_lots`); India direct equity has no dated flows -> `available=false, reason="no lot dates"`; total XIRR over holdings with flows with `coverage_pct` of portfolio value. Algorithm: keep bisection but add Newton polish (or Brent) only if needed for the spreadsheet 0.01% check (bisection to 1e-12 already satisfies it); keep `xirr()` signature. Known-answer: Excel XIRR convention (actual/365, first flow date as origin) on hand-computed vectors; avoid claiming "validated against a spreadsheet" without one (use algebraically solvable cases, e.g. a single outflow and inflow: r = (in/out)^(365/days) - 1, and a two-outflow case verified by substituting back).
- D-H MCP: see Q-1. If included, tools: `ta_compute`, `fa_compute`, `valuation_range`, `portfolio_xray`, `risk_metrics`, `screen`, `score`, `xirr` (names are write-safe; `overlap` and `mf_analyse` already exist as engine functions from E5 and are CLI-only). Output JSON numbers, avoid redaction-trigger key names (`key`, `account`, `token`, `client`, `address`).
- D-I Factor definitions (ADR): Quality = ROCE/ROIC (or ROE for financials), margin stability (std dev), CFO/PAT, leverage; Value = valuation percentile (inverted) vs own history and peers, FCF yield; Growth/revisions = forward growth (estimates) and revision direction (unavailable for India: factor computed from the remaining inputs with `inputs_available` reported, or marked unavailable); Momentum = trend, RS, setup quality; Risk (inverted) = vol, drawdown, hard/soft flags. Each raw factor is converted to a 0-100 percentile within (market, sector) cohort. Composite = sum(weight x factor), weights from config per horizon (30/25/25/10/10 long-term; 15/10/20/45/10 positional per 15.5) with `weights_version`.
- D-J BR-12 enforcement by construction (not only a test): (1) momentum and price-derived risk inputs contribute only to the extent of fundamental support: e.g. `momentum_credit = min(momentum, support_cap(quality, growth, value))` or the composite is capped below the top band when non-price factors average below the config floor; (2) valuation percentile > 90 subtracts a penalty from momentum; (3) INSUFFICIENT_DATA below 70% of required inputs; (4) hard red flag -> `cap="HOLD"`. The property test sweeps momentum = 100 with every combination of other factors below the support floor and asserts composite < top-band threshold, and asserts that setting the non-price factors to None never produces a top-band verdict. The risk factor's volatility/drawdown inputs are price-derived too: classify them as "price-derived" in the ADR so the guard covers them.
- D-K Slice structure (recommended): see "Recommended slices".
