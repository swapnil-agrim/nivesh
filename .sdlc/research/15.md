## Goal in one paragraph
Headless, calendar-aware scheduler (ST-11.1) running brief, login nudge, monitors, reviews and ledger scoring (ST-11.2/3/4/6/7), idempotent per (job, trading date), 2 retries with backoff, failure notice via delivery adapters (NFR-12), UTC stored / IST shown (NFR-19), persisted `Alert` (PID s13 line 377: alert_id, rule, security_id, fired_at, payload, delivered), alert hygiene (5-trading-day dedupe, digest if >3/hour, cap 8/day). Sources: PID ST-11.1..11.7 (lines 1334-1394), FR-34/35 (259-260), NFR-12/19 (283, 290), OBJ-11 (84), J-9/J-10 (168-169), R-6 (1655). Acceptance `.sdlc/acceptance/15.md`; absorbs #97 (watch entry-zone alert). Worktree `.sdlc/work/15`, HEAD b22dc48 (E12 merged). Next SQLite migration **0009**; next ADR **0014** (`docs/adr/0013-ledger-scoring-evaluation.md` is the latest).

## 2. Proposed design (minimal)
- **Pure engine** `nivesh_engine/schedule.py`: `Job` dataclass (name, market NSE|NYSE|none, at_ist HH:MM or weekly/monthly rule, trading_days_only), `due_jobs(jobs, cals, now_utc) -> list[(Job, date)]` using `Calendar.is_session`; weekly (Sat 09:00 IST, Saturday is not a session so "trading days only" = false for reviews), monthly first Saturday; `us_open_ist(day)` via `zoneinfo`; retry/backoff plan helper. `nivesh_engine/alert_rules.py`: Decimal-only rules `big_move(closes, mult)`, `below_invalid(close, level)`, `in_zone(close, low, high)`, `break_52w(bars, vol_mult)`, `mf_changes(prev, cur, ter_pp)`; `hygiene(fired, history, cap, window)` returns (deliver_now, digest, suppressed). Trading-day windows by `Calendar`.
- **Store** `nivesh_core/alerts.py` + migration `0009_alerts_scheduler.sql`: `alert(alert_id INTEGER PK, rule TEXT, security_id INTEGER NULL REFERENCES security, fired_at TEXT UTC, trading_date TEXT, payload TEXT JSON (what/verdict/next step), delivered INTEGER 0/1/2 (2 = batched in digest), digest_id)`; `job_run(job TEXT, trading_date TEXT, status TEXT CHECK(...), attempts INTEGER, run_id INTEGER, started_at, finished_at, reason TEXT, PRIMARY KEY(job, trading_date))` = idempotency (`INSERT ... ON CONFLICT DO NOTHING` then claim). Not append-only for job_run (status updates), alert append-only except `delivered` (use a separate `alert_delivery` insert or allow UPDATE of `delivered` only; simplest: no trigger on alert, document).
- **Runner** `nivesh_adapters/scheduler.py`: `run_due(settings, profile, jobs, now, notifier, sleep, registry)`; job registry `dict[str, Callable[[JobCtx], JobResult]]`; per job: skip if `job_run` done, attempt up to 3 total (initial + 2 retries) with injected `sleep` backoff, on final failure `notifier(Message("nivesh job failed: <job>", reason))` with reason passed through `redact`/`scan_text`. Nudge job `login_nudge` (08:45 IST, once: its own `job_run` row guarantees one-time). `alerts.py` adapter: `evaluate_monitors(...)` reads bars/watch/theses/fund_meta, writes alerts, returns text.
- **CLI** `nivesh_cli/schedule.py`: `nivesh schedule run [--now ISO] [--dry-run]` (the single entry point cron/systemd/launchd calls every 5-15 min; idempotent so overlap is safe), `nivesh schedule status`, `nivesh alerts [--since]`. Register like `scorecard_app` in `main.py`. Docs: `docs/deploy/schedule.md` (+ example `deploy/nivesh-schedule.{service,timer}`, cron line, launchd plist as *text files only*, nothing installed) and `config/schedule.yaml`.

## 3. Risks
1. Size: 7 stories + new tables + CLI + docs; ST-11.5 has no India trigger. Cut as in section 6.
2. DuckDB single-writer: a scheduled ingest/MCP reader collision (`open_duck(read_only=True)` raises `ConnectionException`); the runner must treat as retryable and surface "retry shortly".
3. Cost: scheduled `review holdings` spends model budget unattended; gate exits 1 -> non-retryable, notify "budget cap" once.
4. PII/secret leakage in alert and failure texts: exceptions can carry paths/values; always send `type(e).__name__` + curated reason through `redact`, and `blocked_reason` still scans. Holdings quantities never in payloads.
5. Calendar: NSE holidays incomplete (only 5 dates in 2026) => wrong "trading day" decisions; `CalendarUnknown` must notify and skip; document owner action. NYSE rule-based is OK.
6. Time bugs: UTC stored via `to_iso`, IST-only for display; `ist_date` must decide "trading date"; midnight/DST-crossing tests with fake clock; US 18:30 IST pre-open drifts by an hour across DST (zoneinfo/tzdata availability on slim image).
7. Idempotency under concurrency (two cron fires): claim via PK insert in a `BEGIN IMMEDIATE` txn (pattern: `migrate.py`); `ledger.record_calls` shows the txn style.
8. Alert hygiene semantics: "5 trading days" dedupe must use calendar sessions, not days; digest ">3 in an hour" and cap must be deterministic given `now`; suppressed alerts must still be stored (delivered=0 + reason) for audit.
9. Invalidation level has no numeric source (see Q2); monitors fire on `ledger_entry` latest per security.
10. Coverage gate excludes `nivesh_core`/`nivesh_cli`: keep logic in `nivesh_engine`/`nivesh_adapters`; migration/CLI covered by tests anyway.
11. Secret scanner: avoid identifiers like `secret/token/password/key` in new code/tests (use "session", "ref").
12. Out-of-scope safety: no order/write tools, no crontab edit, no sending in tests (inject notifier; autouse socket block catches slips).

## 5. Open questions with recommended defaults
1. ST-11.5: ship now? Default **defer** with a follow-up issue (needs India results-date/filing detection; US-only exists). Optional cheap US-only trigger (`filing` form 10-Q/10-K new since last run + `next_earnings`) is a stretch; skip.
2. Numeric invalidation level: default = thesis kill criterion with metric `close` (or similar) in `metrics.py` if present, else the latest `ledger_entry.entry_low` is NOT used; if no machine level exists the rule reports `skipped: no numeric invalidation` in `schedule status`. Confirm metric registry has a price metric before choosing; otherwise add optional `invalidation_price` via 0009 ALTER on a new `watch`/thesis-adjacent table (not recommended in this slice).
3. `/review-portfolio` and `/review-funds` do not exist: default jobs run `review holdings` (+ `review rebalance` summary) and `mf doctor` for held schemes through the existing services, saved with `plain_run`/`metered_run` under command names `review-portfolio` / `fund-doctor` (matching `HOLDINGS_COMMANDS`), **saved but not delivered** unless `delivery.include_holdings`-style flag in schedule.yaml (default off) since they list holdings.
4. Weekly review days and trading-day rule: reviews on Saturday are not sessions; jobs carry `trading_days_only` (brief: true, nudge: true, reviews: false).
5. Merger detection: default = scheme `amfi_code` disappears/changes or `scheme_name` contains "merged"/"merger" in latest meta; call it best-effort in the alert text.
6. `schedule run` cadence: every 5 min tick; a job is due when `now >= at_ist` and no `job_run` row for (job, trading_date); late runs allowed up to a per-job `grace_minutes` (brief delivered by 08:30 target -> report `late` in status when >30 min).
7. Alert digest channel text: one summary line per alert, no numbers beyond percentages and levels already public; scan_text before send.
